# Derived objects: scenario catalog

> **Archived.** This catalog maps the prototype's tests to the behaviours they encode. Its row IDs
> (GAP-02, OWN-07, STR-05, ...) are still cited by tests and production comments, so keep them intact.
> It is no longer maintained: its counts, statuses and slice references describe the carving, not the code.

Every use case and corner case that the prototype's tests encode, made explicit. The point
is that no slice of the carve (tracked in a since-deleted carving tracker) drops a scenario silently.
Each scenario is either ported, changed by a named decision, or deliberately deferred.

- **Source.** Branch `feat/derived-objects-editor-host` (PJ4 #697, #698 and #699), compared
  with its merge base on `release-4.1` (`d0138b922`).
- **Scope.** Every test case in a test file the stack added or moved, plus every test case
  the stack added or changed in an existing file: 794 test cases (see
  [Coverage check](#coverage-check)).
- **Rows.** One per scenario. Near-duplicates (Luau and Python twins, fixtures run twice)
  share a row. "Expected behaviour" is what the prototype's test asserts today.
- **Decision references.**
  - D-numbers are in [REQUIREMENTS.md](../../derived_objects/REQUIREMENTS.md).
  - N-numbers and P-numbers point at the review notes and the proposals page.
    [ARCHITECTURE.md](../../derived_objects/ARCHITECTURE.md) holds the resulting design: N1 §14, N3/N5 §12,
    N6 §11, N7 §9, N8 §15, N9 §8, N10 §13.

## How to use it while carving

1. Before cutting a slice, list the rows in the areas it touches.
2. For each row, the slice does one of three things, and writes it in the row's last
   column:
   - **ported:** `slice N: <TestName>`;
   - **changed:** `slice N per <decision>: <NewTestName>`;
   - **deferred:** `deferred: <reason>`.
3. A `keep*` row ports the expectation but rewrites the assertion against the replacement
   machinery.
4. A `blocked` row waits for the decision it names.
5. When a slice closes a [gap](#gaps), it adds a row for it and moves the gap here.

## Status legend

| Status | Meaning |
|---|---|
| `keep` | Port the test as is (renames aside). |
| `keep*` | The scenario is unchanged, but the test asserts on machinery a decision replaces (N1's compile-once, N8's demand gating). Port the expectation and rewrite the assertion. |
| **changes: X** | Expected behaviour changes under decision X. The new expectation follows the dash. |
| **removed: X** | Decision X deletes the machinery the test pins. |
| **blocked: X** | Waits for decision X (an SDK host-contract item). |
| **decided here** | Was unclear in the draft; resolved by a decision recorded in this file (the reason follows). |

Decisions referenced: **D30** (newest completed result wins, one running and one pending request per node, supersede only on meaning change, display only moves forward, lag indicator, D6 clearing unchanged); **N7** (decided 2026-10-14: results stay in the ObjectStore and each derived topic's window is a ring that evicts the oldest publication and never refuses, under one global byte budget; a finding is stored at a fixed early timestamp so it is visible at any instant); **N8** (series stay on on-demand, demand-gated, union clock); **N9** (OnDemandService split, structure only: no row changes status because of it); **N10** (one life-cycle protocol, generators keep topics on restore, persistence leaves MainWindow); **N1** (Python compile once per revision, read-only allowed modules); **N6** (decoding in the worker, native ops release the GIL); **N3/N5** (repeated identical TF samples not stored); **D7** (one dataset per node); **D10** (number outputs of object functions can be series); **D25/D26/D27** from the spec.
