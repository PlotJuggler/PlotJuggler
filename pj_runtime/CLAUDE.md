# pj_runtime

## Purpose

App runtime services and contracts for PlotJuggler 4. This is the **services seam** between the shell (`pj_app`) and the rest of the system: every widget family (`pj_plotting`, `pj_scene2D/widgets`, `pj_scene3D/widgets`) reads from and reacts to services exposed here, but the widget families themselves are siblings and never depend on each other.

## Hard constraints (from root CLAUDE.md)

- Qt is allowed (`Qt6::Core`, `Qt6::Network`, `Qt6::Xml`).
- **`Qt6::Widgets` is forbidden.** No concrete widgets live here. Anything that needs `QWidget` belongs in `pj_widgets` or a widget-family module.
- Public headers under `include/pj_runtime/` are the SDK boundary for the shell and widget modules.

## Public surface

The authoritative source is `include/pj_runtime/`. Today:

| Header | Role |
|---|---|
| `AppSession.h` | Central runtime object. Owns and exposes the services below, including `topicDemandTracker()` (the demand-driven per-topic streaming subscription tracker — see `TopicDemandTracker.h`). `pj_app` instantiates one at startup. **Source Timeline additions:** `datasetRawTimeRange(DatasetId)` returns the raw `[min,max]` absolute-ns bounds across a dataset's catalog-visible topics (used by `SourceTimelineController` to populate bar extents); `recomputeRange()` updates only the `PlaybackEngine` range from the offset-adjusted union of visible topics (called throttled on the drag path — never resets `currentTime` while data remains) and returns that union's display-min, which `seedPlaybackFromSession()` reuses for the first-load playhead snap (one scan, not two); when NO visible data remains it instead collapses the transport to the empty state via `resetPlaybackToEmpty()` (pause, `[0,0]` range, cursor 0), the same reset the `CatalogModel::cleared()` hook runs on a full wipe — this is what stops playback and resets the slider when the last dataset is removed. Both are implemented via a shared `forEachVisibleRawRange` private scan so visibility/dedup rules live in one place. `mergeDatasets(selected)` **destructively** folds the selected datasets into one (the OR/union): the anchor = leftmost-in-display dataset keeps its clock + ids, the others are shifted into it by their relative display offset and removed from the catalog, scalar topics union by name, object topics fuse by name, and the anchor is relabelled `*_merged` (returns the anchor id). `AppSession::objectMergeConflicts(selected)` is the canonical builtin-object-type preflight; on successful merge AppSession emits `datasetsMerged(anchor, consumed)`. |
| `SessionManager.h` | Session lifecycle (load/clear/active dataset). Also owns and exposes the session's `CurveColorRegistry` so plot widgets can reach it through their existing `SessionManager` pointer. **Source Timeline additions:** `setDisplayOffset(DatasetId, DisplayOffset)` writes a per-source display shift to the underlying `TimeDomain` and emits the per-dataset `displayOffsetChanged(DatasetId)` — idempotent, so an unchanged offset emits nothing (no spurious replot/rebuild); it is consumed by `PlotWidget` (drops that dataset's adapter offset cache, refreshes the max zoom-out extent + magnifier limits, and replots at current zoom) and by `SourceTimelineController` (refreshes the bar offsets + triggers throttled `recomputeRange`). This per-source signal is **overloaded against** the no-arg `displayOffsetChanged()` that the global "Use time offset" frame (`setUseTimeOffset`) emits — connect either with `qOverload<>` / `qOverload<PJ::DatasetId>`. **Time-offset model (decoupled):** the total `displayOffset(id)` that everything on the display axis reads (plot curves, scenes, playback range/cursor) = the per-source *alignment* shift (`sourceDisplayOffset(id)`, the TimeDomain offset the Source Timeline edits) **plus** a single global `globalTimeReference()` (the earliest raw sample across all datasets when "Use time offset" is on, else 0 — applied **uniformly** so cross-dataset time gaps are preserved, not a per-source rebase). `setUseTimeOffset` flips *only* the global reference and never writes per-source offsets, so toggling never disturbs the Timeline's bar positions. The Source Timeline reads `sourceDisplayOffset` for its bars (align-only frame) and the host (`SourceTimelineController`) bridges `globalTimeReference` across the playback↔timeline frame gap. **Dataset removal:** `removeDataset(DatasetId)` is the seam for a real delete — it erases the dataset's scalar storage from the `DataEngine` AND invalidates the time-origin caches (`globalTimeReference()` re-bases to the survivors), so callers must use it rather than reaching into `dataEngine().removeDataset` directly (which would leave the memoized earliest-sample origin stale when the earliest dataset is removed); when that re-base actually moves the origin it emits `displayOffsetChanged()` so surviving curve adapters drop their now-stale offsets and re-fit; it also drops the dataset's source-path registry entry. **Dataset identity registry:** owns the `DatasetId` → normalized-full-path map (`setDatasetSourcePath`/`datasetSourcePath`, written by `pj_app`'s `FileLoader` — `DatasetInfo::source_name` is only a display label and cannot distinguish same-basename files) and `resolveDatasetIdentity(id, source, path)`, which resolves a persisted identity without ever guessing by load order: exact live id (trusted only while the saved qualifiers still agree) → unique full-path match → unique source-name match → reject with `DatasetIdentityResolution::ambiguous` (nullopt id + `ambiguous=false` = not loaded yet). `resolveObjectDatasetIdentity` adds an object-topic-name tiebreak for same-file fan-out siblings. **Token-addressed progressive ingest:** manages a dataset's load stream via `IngestToken` (`quint64`-addressed; 0 = invalid). `beginIngest(DatasetId, label, total, cancellable, cancel_fn)` starts a stream; **a new `beginIngest` on a dataset supersedes any prior token**, invalidating the old token's pending `updateIngest`/`endIngest`/`requestCancel` calls (they become silent no-ops) and **reporting the superseded run's terminal as `ingestEnded(old_token, kCancelled)`** before the new `ingestBegan` — so no observer has to infer a supersede from the next began, or leak what it bound to the old token. At most ONE ingest per dataset is tracked (the dataset IS the identity; the entry carries its token id), and the single `liveEntry(token)` lookup is the one definition of token staleness. `updateIngest(token, current, total)` publishes that dataset's flushed topics **before the staleness gate** — preventing a publish-ordering slip from ever dropping data — and reports `ingestProgressed` **factually**, including after a stop was requested (the producer keeps delivering until it notices): freezing a stopping row's bar is presentation policy and lives in `IngestProgressController`, not here; `endIngest(token, outcome)` closes the stream. **Cancellation intent wins:** `requestCancel(token, keep_partial)` records cancellation intent, so whichever terminal (`endIngest` or a late `requestCancel`) arrives after intent **reports `kCancelled` regardless** of what the producer passed; a cancel after the terminal is refused. **`kUnknown` outcome exists** because the plugin C-ABI's `on_ingest_finished` carries no outcome code — reporting `kCompleted` would assert a success nobody observed. Observable surface: `ingestActive(DatasetId)` checks current status, `activeIngests()` snapshots the full set (label/current/total/cancellable state), signals `ingestBegan` / `ingestProgressed` / `ingestEnded` fire for shell binding. Paired view layer: `CurveTreeView` in `pj_widgets` renders per-dataset progress bars (row-spanning fill plus, on a cancellable row, TWO stop affordances — ✕ = stop and keep, bin = stop and discard — reported as `cancelRequested(row_key, keep_partial)`, so the host acts on the user's choice instead of prompting for it; honouring `keep_partial` is the producer's job); `IngestProgressController` in `pj_app` keys each row by its ingest id (the row key IS `IngestToken::id`, so a click resolves back to its ingest by lookup) and owns UI lifetime policy (1 s completion linger, ~180 ms error flash per `State::kFailed`, ghost rows for discarded loads, display-name feed, and the frozen bar of a `kStopping` row). Title-bar progress strip (`IngestProgressWidget`) is API-retained but suppressed via `constexpr kShowTitleBarIngestStrip=false` at its show seam. |
| `MarkerService.h` | Host service backing the unified **`pj.data_processors.v1`** SDK service for `kind=markers` — the **object engine**. Runs plugin-submitted **whole-series** generators via `pj_scripting`'s `runMarkerScript` and publishes the resulting `PlotMarkers` to the `ObjectStore` (`__markers__/…`). **Invariant: writes ONLY to the `ObjectStore`, never the `DataEngine`** — timeseries outputs come from transform generators (`kind=transform` → `DerivedEngine`), not here. Owned by `SessionManager` (`markerService()`); the shell injects a catalog-backed series resolver + dataset lister. Supports ephemeral previews (excluded from persistence) and global-across-all-datasets generators. Re-runs on commit/reload via `recomputeForChangedInputs`. (Class name kept; an `ObjectEngine` rename to admit object kinds beyond markers is a future cosmetic step.) |
| `ObjectIngestTap.h` | Session-scoped exclusive consumers for builtin object bytes. Runtime hosts invoke a claimed kind synchronously after scalar parsing and before ObjectStore registration; the payload view is call-lifetime only. `SessionManager` owns the shared registry used by file, streaming, and delegated toolbox ingest. |
| `MarkersRuntimeHost.h` | Host-side bridge that exposes the kind="markers" path of the unified **`pj.data_processors.v1`** SDK service to a plugin and delegates to `MarkerService` — the markers sibling of `ToolboxRuntimeHost`. Accepts only `kind=markers` (`"transform"` is routed to the DerivedEngine bridge owned by the transform-editor work). Implements the C-ABI vtable (per-plugin id namespacing), constructed per toolbox bind in `MainWindow`. Not movable (the vtable stores `this`); the generators it creates outlive it (the host owns the runtime). |
| `CatalogModel.h` | Catalog of curves, objects, and data sources available to the UI. Also carries the demand-subscription surface: advertised-but-unsubscribed placeholders (`setAdvertisedTopics`, data-less rows real data supersedes) and the per-dataset `setPerTopicPauseCapable`/`isPerTopicPauseCapable` flag (set by `StreamingSourceManager` at session start/stop) that gates every demand-driven UI affordance — dimming, census previews, the force-streaming menu — so file datasets and non-demand sources are never misrepresented as pausable. **Identity facade:** re-exposes the session's dataset-identity surface for layout/plot binding (`datasetSourceName` — the raw `DatasetInfo::source_name`, not the deduped display label; `resolveDatasetIdentity`; `datasetSourcePath`), so widget code needs no separate `FileLoader` dependency. `resolveCurveKey(saved_id, saved_source, saved_path, topic, field, capability)` is the shared three-tier curve resolver both layout/undo restore (`PendingDisplayBinder::resolveSeriesPath`) and clipboard paste (`PlotWidget`) call, so the exact-id / unique-full-path / unique-source / reject-ambiguity algorithm lives in one place; its `SeriesCapability` parameter filters matches by consumer family (`kPlottable` for plot curves — the default — vs `kDiscrete` for State Transitions rows), backed by the `ScalarFieldPayload::logical_type` primitive and the `isPlottablePrimitive`/`isDiscretePrimitive` predicates (integers/bool satisfy both; floats plot-only; strings discrete-only). |
| `Time.h` | Display-relative time vocabulary: `DisplayOffset`, `DisplaySeconds`/`DisplayRange` (the Qwt/playback display-axis coordinate), the display adapters (`offsetOf`, `rawToDisplaySeconds`, `toAxisDouble`, …), and `kNanosecondsPerSecond`. Layered on the absolute spine (`Timepoint`/`Duration`/`fromRaw`/`toRaw`) in the SDK at `pj_base/time.hpp`, so every layer can name absolute time; the display coordinate stays here because the per-dataset offset is an app-presentation policy, not an SDK concern. |
| `PlaybackEngine.h` | Time cursor + playback (play/pause/seek/loop). Public API speaks `DisplaySeconds`/`DisplayRange`; the `currentTimeChanged(double)` signal + `IDataWidget::onTrackerTime(double)` stay `double` (a fleet-wide moc/vtable contract). |
| `DataSourceRuntimeHost.h` | Host-side runner for `DataSource` plugins from `pj_plugins`. Threads a **plugin-DSO keepalive** (`shared_ptr<void>` from `DataSourceHandle::libraryOwner()`) into every lazy payload anchor + fetch closure, deferring `dlclose` until the last anchor/parser drops — so a decode worker never calls plugin code (`release`/`parseObject`) in an unmapped `.so`. Pitfall: a plugin `release` may run on an arbitrary worker thread during/after teardown (see the header). Implements `notify_available_topics` (`cbNotifyAvailableTopics`): classifies each advertised topic a priori (bind a throwaway `MessageParserHandle`, `bindSchema` + `classifySchema` — no `bind(registry)` needed; falls back to matching the type name against `FrameTransforms`/`CameraInfo` when no parser is registered or `classify_schema` returns `kNone`) and hands the classified set to the optional `on_available_topics` callback, which fires on the **poll/stream thread** — the callback owns marshaling to the GUI thread (`pj_app`'s `StreamingSourceManager` does this, feeding `CatalogModel::setAdvertisedTopics` + `TopicDemandTracker::setInfrastructureTopics`). `cbEnsureParserBinding` is **idempotent per request signature** (topic + encoding + type + schema + parser config): a demand-driven plugin re-requests its binding on every re-subscribe, and handing back the existing binding is what prevents a duplicate engine topic (`DataEngine::createTopic` mints a fresh TopicId per call, no name dedup) from doubling every field in the catalog; a changed signature (retyped topic) still mints a fresh binding. |
| `ToolboxRuntimeHost.h` | Host-side runner for `Toolbox` plugins: assembles `ToolboxHostService` (write surface) + `ToolboxRuntimeHostService` (diagnostics / data-changed) + `SettingsStoreService` into a `ServiceRegistry`. App concerns are injected as `Callbacks`; the `[thread-safe]` report/notify callbacks marshal onto the constructing (GUI) thread. With optional `ParserIngestDeps` (extension catalog + render-parser registrar), the `create_parser_ingest`/`release_parser_ingest` tail slots hand a toolbox-created dataset the standard `DataSourceRuntimeHost` delegated-ingest surface (one per dataset; release = flush + destroy, idempotent; driven from the toolbox worker thread, not GUI-marshalled). `on_data_changed` reports the bulk-import datasets so the shell can focus playback on them: contexts created/released since the previous notify (drained per notify) **plus** every context currently mid-import (between `progress_start` and `progress_finish` on the ingest fat pointer) — so a progressive import keeps its focus as it grows. The ingest fat pointer's progress slots also drive the progressive-import surface: each unthrottled `progress_update` (default 50 ms, `setFlushThrottleMs` test seam) flushes BOTH write surfaces (parser bindings + the toolbox write host) on the plugin's ingest thread, then fires the GUI-marshalled `on_ingest_started/progress/finished` callbacks — so a shell handler can treat every `on_ingest_progress` as "new rows are reader-visible" and publish incrementally (`pj_app` mirrors `FileLoader::publishIngestProgress`). `requestStopActiveIngests()` is the shell's stop affordance: flag-only cooperative cancel every live context reports through `is_stop_requested` / `progress_update == false` (keep-partial semantics; the toolbox ABI has no host-side rollback). |
| `DataProcessorService.h` | Applies "Data Processors" as eager `DerivedEngine` nodes. Two tiers of one substrate: **filters** (per-curve, hidden output, keyed by output topic) via `applyFilter`/`updateFilter`/`clearAllFilters`; **transforms** (named, plugin-owned, session-persisted, keyed `"<plugin>/<id>"`) via `upsertTransform`/`removeTransform`/`restoreTransform`/`transformRecipes`. Transform recipes capture dataset/source/topic/field input identity; replacing reloads use `rebindAndRecomputeForReplacedSources` to update semantic column bindings in place while preserving output TopicIds. Compatible script edits replace operators transactionally, structural edits reject before mutation, and removal cascades by exact TopicId. `sourceTopicsForOutput(TopicId)` walks mixed processor chains to their exact raw subscription topics. |
| `DataProcessorsRuntimeHost.h` | Host-side bridge exposing the `pj.data_processors.v1` SDK service to ONE plugin over `DataProcessorService` (data-only; every id namespaced under the plugin; all slots `[main-thread]`, so no Qt / no marshalling). A created transform OUTLIVES the bridge — destroying it (DSO unload) leaves the node running; only an explicit `remove`/`clearTransformsForPlugin` tears it down. |
| `QSettingsBackend.h` | `sdk::SettingsBackend` implemented over `QSettings` (→ `PlotJuggler4.conf`); injected into `ToolboxRuntimeHost` so plugin settings persist. `'/'`-separated keys map to `.conf` groups. |
| `ExtensionCatalogService.h` | Marketplace-backed extension catalog (queries `pj_marketplace`). Composes the loaded plugin set via `PluginRuntimeCatalog` over the scan hierarchy `--plugin-dir` (authoritative) → custom Preferences folders (authoritative) → marketplace dir (managed). At construction (every mode) it **seeds** the bundled dir `<prefix>/lib/plotjuggler/plugins` into the default marketplace dir — copy when absent, staged refresh when the bundled version is newer, and never downgrade a compatible install; a copy the current host would reject for a malformed plugin version or under the shared ABI + `min_sdk_required` + `min_plotjuggler_version` gate (see `descriptorIncompatReason`) is rescued by overwriting it with the bundled build, since the bundled dir is never scanned as a load path and would otherwise leave the id dead. It hands the bundled id→version map to the `ExtensionManager` (core-plugin uninstall lock) in default sessions only; the bundled dir itself is never scanned. `Paths` constructor = test seam for all three roots. Browser/static builds skip the marketplace and register their application-composed `StaticPluginSet` before scanning. |
| `PluginRuntimeCatalog.h` | Host-side plugin catalog: scans the folder hierarchy via the SDK's `scanPluginDsos`, resolves duplicate ids by **authoritative → compatibility → version → folder priority**, then hard-rejects a winner with a malformed version or incompatible host contract before loading it through the SDK loader. An authoritative copy still shadows every managed same-id fallback, so a broken `--plugin-dir` build fails visibly instead of silently testing a different plugin. This resolution is host policy — it was relocated here from the SDK so the SDK stays a thin discovery/loader layer. `registerStaticPlugins(const StaticPluginSet&)` applies the same admission gate to plugins linked directly into the binary (data sources, message parsers, and toolboxes with optional companion dialog vtables), which is the WASM path when dynamic loading is unavailable. |
| `DiagnosticHistory.h` | Ring buffer of diagnostics surfaced via `pj_base::DiagnosticSink`. |
| `IDataWidget.h` | The contract every data widget (plot / 2D / 3D) implements so playback can drive tracker updates without coupling to concrete widget types. |
| `IObjectViewer.h` | The contract an object-store-backed viewer (e.g. a 2D image dock) implements so the shell can ask it to drop layers whose object topic was removed; returns whether any live layer remains. Pairs with `CatalogModel`'s `cleared()` / `itemsRemoved()` removal signals. |
| `CurveDescriptor.h` | Stable identifier for a curve in the datastore. |
| `CurveColorRegistry.h` | Session-scoped memory of each curve's color (hex string), so a curve keeps its color across plots (issue #68). Owned by `SessionManager` (and surfaced via `AppSession::curveColorRegistry()`); cleared when the catalog empties. |
| `TopicDemandTracker.h` | Demand-driven per-topic streaming subscriptions: computes, per streaming dataset, the active set = displayed (ref-counted `addReference`/`removeReference(DatasetId, topic_name)`) ∪ infrastructure (`setInfrastructureTopics` — TF/CameraInfo) ∪ user-forced (`setTopicForced` — the curve-tree "Force topic streaming" context action; a tier, never an override, so unforcing cannot pause a displayed topic; `forcedTopicsChanged` fires even when the active set doesn't, for UI badging). Emits `activeTopicsChanged(dataset_id, sorted-unique names)` only on change. GUI-thread only; owned by `AppSession`. A *pending* display intent counts as a reference too (`pj_app`'s `PendingDisplayBinder`), or a restore/placeholder-drop bind would deadlock (no subscription → no data → binding never completes). `pj_app`'s `StreamingSourceManager` wires the emitted set to `DataSourceHandle::setActiveTopics` (capability-gated on `kCapabilityPerTopicPause`); `pj_app`'s `TopicDemandController` produces references from displayed plots/scene docks AND owns the bounded field-discovery previews: an advertise burst auto-previews every kNone-classified placeholder (census, ≤8 concurrent, once per topic per session), a double-click peeks manually, each preview holding a reference until promotion or a ~4 s timeout — and a preview-promoted topic's fake-interest samples are disowned (`DataEngine::evictTopicHistory`) the moment a real reference arrives, so they never draw a bogus flat segment. |
| `HttpGet.h` | `httpGetWithTimeout()` / `httpPostWithTimeout()` — the one-shot async request idiom shared by `UpdateChecker`, `TelemetryPing`, and `pj_app`'s Preferences registry-URL reachability probe: caller-configured `QNetworkRequest` (the POST variant adds a body; set Content-Type yourself), transfer timeout, callback with the finished reply on the caller's thread (fires on error/abort/timeout too), reply `deleteLater`'d after the callback returns (callers must not retain it). Returns the in-flight reply so supersede/abort patterns work. |
| `TelemetryPing.h` | Fire-and-forget POST of the anonymous launch-ping payload to app.plotjuggler.io (a `httpPostWithTimeout`, default SSL verification, 15 s timeout). The payload is built internally in `TelemetryPing.cpp` — the privacy contract (environment facts only, salted-hash user id, PJ3-compatible keys) is enforced on the wire by `telemetry_ping_test`'s allowed-key set; extending the payload means updating that test + `docs/TELEMETRY.md` together. Emits `finished(ok)` once per send; the reply body is ignored, nothing is ever surfaced to the user, and all failures are silent. The shell owns the opt-out gate (`Preferences::send_anonymous_stats`). |
| `UpdateChecker.h` | One-shot GitHub "new release available?" check (a `httpGetWithTimeout` GET of `releases/latest`, `User-Agent` set, default SSL verification). Compares the returned tag against `applicationVersion()` and emits **at most one** of `updateAvailable(ReleaseInfo)` / `upToDate()` / `checkFailed(reason)` (a check superseded by a newer `checkLatestRelease()` is aborted and emits nothing); every failure (network, HTTP 404 = no release yet, bad JSON, unparseable tag) routes to `checkFailed`, so the shell can stay silent on the startup path. Widget-free — the shell wires `updateAvailable` to a toast. |
| `UpdateVersion.h` | Header-only version math behind `UpdateChecker`: `versionToComparable()` (tolerates a `v` prefix, `-rc`/`+build` suffixes, missing components; `-1` on garbage) and `isNewerVersion(candidate, current)` (strict, false unless both parse). Radix leaves room for a 3-digit minor (our beta is `3.999.0`). Unit-tested in `tests/update_version_test.cpp`. |

## Linked dependencies

Public link surface (per `CMakeLists.txt`): `Qt6::Core`, `Qt6::Network`, `Qt6::Xml`, `pj_datastore`, `pj_marketplace`, the SDK discovery primitives (`pj_data_source_host`, `pj_message_parser_host`, `pj_toolbox_host`, `pj_plugin_catalog`, `pj_base`), `nlohmann_json`. Private: `tsl::robin_map`, `pj_internal_fmt`, `pj_scripting` (DataProcessorService routes by-id applyFilter through the Luau FilterCatalogue; MarkerService runs whole-series rules through `runMarkerScript`).

The `pj_marketplace` link is conditional: `$<$<NOT:$<BOOL:${EMSCRIPTEN}>>:pj_marketplace>` in `pj_runtime/CMakeLists.txt` links it only on non-wasm builds. On `EMSCRIPTEN`, `pj_runtime` instead adds `pj_marketplace/include` as a private include directory (so `DiagnosticHistory`'s lightweight `QtDiagnosticBridge` type still compiles) without linking the rest of the marketplace module.

## When porting from PJ3

PJ3 wiring into `PlotDataMapRef` / `TransformsMap` becomes wiring into the services above — primarily `CatalogModel`, `SessionManager`, `PlaybackEngine`, and (future) `TransformRegistry`. This is the **one systematic rewrite** during a PJ3 port; everything else should be lifted close to verbatim.

## Tests

`tests/` — gtest-based, one binary per service (`app_session_test`, `catalog_model_test`, …). Add tests alongside any new service.
