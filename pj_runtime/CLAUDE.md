# pj_runtime

## Purpose

App runtime services and contracts for PlotJuggler 4. This is the **services seam** between the shell (`pj_app`) and the rest of the system: every widget family (`pj_plotting`, `pj_scene2D/widgets`, `pj_scene3D/widgets`) reads from and reacts to services exposed here, but the widget families themselves are siblings and never depend on each other.

## Hard constraints (from root CLAUDE.md)

- Qt is allowed (`Qt6::Core`, `Qt6::Network`, `Qt6::Xml`).
- **`Qt6::Widgets` is forbidden.** No concrete widgets live here. Anything that needs `QWidget` belongs in `pj_widgets` or a widget-family module.
- Public headers under `include/pj_runtime/` are the SDK boundary for the shell and widget modules.

## Public surface

The authoritative source is `include/pj_runtime/`. Today:

| Header | Role |
|---|---|
| `AppSession.h` | Central runtime object. Owns and exposes the services below, including `topicDemandTracker()` (the demand-driven per-topic streaming subscription tracker — see `TopicDemandTracker.h`). `pj_app` instantiates one at startup. **Source Timeline additions:** `datasetRawTimeRange(DatasetId)` returns the raw `[min,max]` absolute-ns bounds across a dataset's catalog-visible topics (used by `SourceTimelineController` to populate bar extents); `recomputeRange()` updates only the `PlaybackEngine` range from the offset-adjusted union of visible topics (called throttled on the drag path — never resets `currentTime` while data remains) and returns that union's display-min, which `seedPlaybackFromSession()` reuses for the first-load playhead snap (one scan, not two); when NO visible data remains it instead collapses the transport to the empty state via `resetPlaybackToEmpty()` (pause, `[0,0]` range, cursor 0), the same reset the `CatalogModel::cleared()` hook runs on a full wipe — this is what stops playback and resets the slider when the last dataset is removed. Both are implemented via a shared `forEachVisibleRawRange` private scan so visibility/dedup rules live in one place. `mergeDatasets(selected)` **destructively** folds the selected datasets into one (the OR/union): the anchor = leftmost-in-display dataset keeps its clock + ids, the others are shifted into it by their relative display offset and removed from the catalog, scalar topics union by name, object topics fuse by name, and the anchor is relabelled `*_merged` (returns the anchor id). `AppSession::objectMergeConflicts(selected)` is the canonical builtin-object-type preflight (also reporting same-named marker topics whose scope, target or owner differ); on successful merge AppSession emits `datasetsMerged(anchor, consumed)`. |
| `SessionManager.h` | Session lifecycle (load/clear/active dataset). Also owns and exposes the session's `CurveColorRegistry` so plot widgets can reach it through their existing `SessionManager` pointer. `displayTimeForSource(DatasetId, absolute_ns)` maps a raw instant onto the display axis under that dataset's current `displayOffset` (nullopt for an unknown dataset) — the `pj.playback.v1` conversion slot. `removeEphemerals(transform_keys, generator_ids)` ends the listed previews still present and still ephemeral in both derived engines (`DataProcessorService` and `BatchEngine`), repainting the overlays once when a marker preview went; `DerivedRuntimeHosts`' destructor passes it the previews its bridges created, so a preview ends with the plugin instance that made it, not with every instance of its plugin. It also wires `DataProcessorService::setOutputsChangedSink` to `BatchEngine::recomputeForChangedInputs(names, dataset)`, so a processor output that changes (a transform upsert or in-place edit, a filter apply, edit or removal, a completed time-sliced replay, a transform removal) marks the marker rules reading it stale. **Source Timeline additions:** `setDisplayOffset(DatasetId, DisplayOffset)` writes a per-source display shift to the underlying `TimeDomain` and emits the per-dataset `displayOffsetChanged(DatasetId)` — idempotent, so an unchanged offset emits nothing (no spurious replot/rebuild); it is consumed by `PlotWidget` (drops that dataset's adapter offset cache, refreshes the max zoom-out extent + magnifier limits, and replots at current zoom) and by `SourceTimelineController` (refreshes the bar offsets + triggers throttled `recomputeRange`). This per-source signal is **overloaded against** the no-arg `displayOffsetChanged()` that the global "Use time offset" frame (`setUseTimeOffset`) emits — connect either with `qOverload<>` / `qOverload<PJ::DatasetId>`. **Time-offset model (decoupled):** the total `displayOffset(id)` that everything on the display axis reads (plot curves, scenes, playback range/cursor) = the per-source *alignment* shift (`sourceDisplayOffset(id)`, the TimeDomain offset the Source Timeline edits) **plus** a single global `globalTimeReference()` (the earliest raw sample across all datasets when "Use time offset" is on, else 0 — applied **uniformly** so cross-dataset time gaps are preserved, not a per-source rebase). `setUseTimeOffset` flips *only* the global reference and never writes per-source offsets, so toggling never disturbs the Timeline's bar positions. The Source Timeline reads `sourceDisplayOffset` for its bars (align-only frame) and the host (`SourceTimelineController`) bridges `globalTimeReference` across the playback↔timeline frame gap. **Dataset removal:** `removeDataset(DatasetId)` is the seam for a real delete — it erases the dataset's scalar storage from the `DataEngine` AND invalidates the time-origin caches (`globalTimeReference()` re-bases to the survivors), so callers must use it rather than reaching into `dataEngine().removeDataset` directly (which would leave the memoized earliest-sample origin stale when the earliest dataset is removed); when that re-base actually moves the origin it emits `displayOffsetChanged()` so surviving curve adapters drop their now-stale offsets and re-fit; it also drops the dataset's source-path registry entry. **Dataset identity registry:** owns the `DatasetId` → normalized-full-path map (`setDatasetSourcePath`/`datasetSourcePath`, written by `pj_app`'s `FileLoader` — `DatasetInfo::source_name` is only a display label and cannot distinguish same-basename files) and `resolveDatasetIdentity(id, source, path)`, which resolves a persisted identity without ever guessing by load order: exact live id (trusted only while the saved qualifiers still agree) → unique full-path match → unique source-name match → reject with `DatasetIdentityResolution::ambiguous` (nullopt id + `ambiguous=false` = not loaded yet). `resolveObjectDatasetIdentity` adds an object-topic-name tiebreak for same-file fan-out siblings. **Token-addressed progressive ingest:** manages a dataset's load stream via `IngestToken` (`quint64`-addressed; 0 = invalid). `beginIngest(DatasetId, label, total, cancellable, cancel_fn)` starts a stream; **a new `beginIngest` on a dataset supersedes any prior token**, invalidating the old token's pending `updateIngest`/`endIngest`/`requestCancel` calls (they become silent no-ops) and **reporting the superseded run's terminal as `ingestEnded(old_token, kCancelled)`** before the new `ingestBegan` — so no observer has to infer a supersede from the next began, or leak what it bound to the old token. At most ONE ingest per dataset is tracked (the dataset IS the identity; the entry carries its token id), and the single `liveEntry(token)` lookup is the one definition of token staleness. `updateIngest(token, current, total)` publishes that dataset's flushed topics **before the staleness gate** — preventing a publish-ordering slip from ever dropping data — and reports `ingestProgressed` **factually**, including after a stop was requested (the producer keeps delivering until it notices): freezing a stopping row's bar is presentation policy and lives in `IngestProgressController`, not here; `endIngest(token, outcome)` closes the stream. **Cancellation intent wins:** `requestCancel(token, keep_partial)` records cancellation intent, so whichever terminal (`endIngest` or a late `requestCancel`) arrives after intent **reports `kCancelled` regardless** of what the producer passed; a cancel after the terminal is refused. **`kUnknown` outcome exists** because the plugin C-ABI's `on_ingest_finished` carries no outcome code — reporting `kCompleted` would assert a success nobody observed. Observable surface: `ingestActive(DatasetId)` checks current status, `activeIngests()` snapshots the full set (label/current/total/cancellable state), signals `ingestBegan` / `ingestProgressed` / `ingestEnded` fire for shell binding. Paired view layer: `CurveTreeView` in `pj_widgets` renders per-dataset progress bars (row-spanning fill plus, on a cancellable row, TWO stop affordances — ✕ = stop and keep, bin = stop and discard — reported as `cancelRequested(row_key, keep_partial)`, so the host acts on the user's choice instead of prompting for it; honouring `keep_partial` is the producer's job); `IngestProgressController` in `pj_app` keys each row by its ingest id (the row key IS `IngestToken::id`, so a click resolves back to its ingest by lookup) and owns UI lifetime policy (1 s completion linger, ~180 ms error flash per `State::kFailed`, ghost rows for discarded loads, display-name feed, and the frozen bar of a `kStopping` row). Title-bar progress strip (`IngestProgressWidget`) is API-retained but suppressed via `constexpr kShowTitleBarIngestStrip=false` at its show seam. **Loader-metadata registry:** `setDatasetMetadata`/`datasetMetadata`/`clearDatasetMetadata` hold one loader-supplied JSON document per dataset (attributed to the emitting plugin; bounds in `validateDatasetMetadata` — object root, ≤1 MiB, depth ≤32, ≤16384 values; rejection keeps the previous document and never affects ingest) — the third sibling of the source-path/source-record registries with the same lifecycle: erased by `removeDataset`, invalidated for every contributor of a destructive merge, cleared by a committed refill (`RefillGuard::commit`). `FileLoader` publishes each load's staged document (`DataSourceRuntimeHost::stageLoaderMetadata`, fed by the SDK `set_dataset_metadata` slot) at the same commit seams that set source paths; `CatalogModel::datasetMetadata` is the read-only facade, and the curve tree's Info dialog renders the document generically. |
| `BatchEngine.h` | Host service backing the unified **`pj.data_processors.v1`** SDK service for `kind=markers` — the **object engine**. Runs plugin-submitted **whole-series** generators via `pj_scripting`'s `runMarkerScript` and publishes the resulting `PlotMarkers` to the `ObjectStore` (`__markers__/…`). **Invariant: writes ONLY to the `ObjectStore`, never the `DataEngine`** — timeseries outputs come from transform generators (`kind=transform` → `IncrementalEngine`), not here. Owned by `SessionManager` (`batchEngine()`). Supports ephemeral previews (excluded from persistence) and global-across-all-datasets generators. **Execution (`docs/derived_objects/ARCHITECTURE.md` §11), a `QObject`:** a run is staged on the GUI thread (`stageRun`: the resolver copies the input series, only the optional raw-ns `GeneratorRecipe::window`, and the copy is clipped to it again), computed on the session's `EnginePool` (`setPool`; `SessionManager` owns the pool, and without one runs go inline) by the static `computeRun`, which touches only that copy, and published on the GUI thread, which queues ONE `markersPublished()` per burst (`SessionManager` forwards it as `markersChanged`, so the plots refresh once per pool drain). `recomputeForChangedInputs` and `reachNewDatasets` run nothing: they mark the affected bindings stale and arm the brake. `Mode::kAutomatic` (default) runs the stale bindings that have no run in flight and whose dataset is demanded through a single-shot brake at `reloadHz()` (`kDefaultReloadHz` = 2, clamped to [`kMinReloadHz`, `kMaxReloadHz`] = [0.2, 20]); `Mode::kManual` waits for `refresh(id)`/`refreshAll(dataset)`, which ignore the brake, the mode and demand. `Settings` + `loadSettings`/`saveSettings`/`setSettings` own the Preferences keys (`Preferences::derived_batch_mode`, `Preferences::derived_batch_reload_hz`): `pj_app` applies them at startup and on OK, and the dataset menu's "Refresh derived" calls `refreshAll`. `AppSession` injects the catalog-backed resolver (`CatalogModel::findScalarForMarkerKey`, then a range-cursor copy of the window), the dataset lister and the demand predicate ("the dataset is not a demand-capable stream, or `TopicDemandTracker::hasAnyReference`"), and connects `referenceDemandChanged` and `activeTopicsChanged` to `demandChanged()`; an `all_datasets` rule is demanded when one of its contributors is. Manual mode stops an armed brake, and a binding whose run failed is not resubmitted by the brake until its inputs change. The result policy (D30) is stated once, in the `BatchEngine.h` class comment. `upsertGenerator` compiles and stages on the GUI thread; its `CreateWait` says how long the caller is held: `kToCompletion` (the default; `MarkersRuntimeHost`, since released plugins read the markers right after create, and an undo or redo, `DerivedObjects::restore` under `kHistory`, since the user expects the previous markers back, not a blank set while the run finishes; it creates only the rules it changed, an unchanged one stays as it is drawn) computes on the calling thread, `kBounded` (a layout load, `DerivedObjects::restore` under `kReplace`, the progressive drain included) computes on the pool and waits at most `kCreateBudget` (8 ms, the transform first-slice precedent; `setCreateBudgetForTest` is the test seam, which `pj_app`'s GUI test environment sets generously): a failure known by then is returned with nothing changed, a run still going carries on as the binding's scheduled run (`isRunning`/`runningIds`, the queued `runningChanged`). A failure no caller hears (a scheduled run, a late bounded create, a whole-dataset recompute) reaches `setDiagnosticSink` (`AppSession` passes the app's sink) once per distinct error: "Marker rule '<id>' failed: … Any previous markers are kept; fix the rule and apply it again." `recomputeForDataset` and `clearGeneratorsForDataset` stay synchronous: their callers repaint from the topics they return, and a rollback must be complete when it returns. `cancelRunsOn(dataset)` cancels the runs reading a dataset: `RefillGuard` calls it when a refill begins, `remapGeneratorsToAnchor` at a merge (which then marks the anchor's and the all-datasets bindings stale). A streaming tick (`SessionManager::recomputeMarkersForChanged`) reports a topic as changed when its newest timestamp, row count, retention floor or series generation moved. `coverageOf(id)` reports the raw-ns range the last published run staged. A cancelled run also stops inside the script (`computeRun` hands its `CancelToken` to `runMarkerScript`, which polls it from the Luau interrupt), so the pool thread is freed at once, and a run whose markers exceed `runMarkerScript`'s 16 MiB output ceiling fails like any script error. (Class name kept; an `ObjectEngine` rename to admit object kinds beyond markers is a future cosmetic step.) **Publish model: one object topic per owner.** Every generator writes its own topic, named `__markers__/<key>#<id>` (`markerOwnerTopicName`, `MarkerTopics.h`; an opaque id) and registered with metadata that says what it is (the markers type, `pj_derived: "markers"`, scope, target and owner: `markerTopicMetadataJson`, `pj_datastore/marker_topic_metadata.hpp`), and a marker topic is a **family** — a direct toolbox write plus one topic per generator — that the overlay reads as a union (`markerTopicsOf`, which matches the metadata of the dataset's topics). So a Dataset-scope (`__global__`) and an all-datasets-scope (`__all__`, normalized from `all_datasets` output in `upsertGenerator`) rule coexist on one dataset, two generators on one key never clobber each other, retiring one tombstones only its own topic, and a direct write is never read or rewritten by the service; the store is the only copy, so there is no in-memory ledger to reconcile. Recipes are keyed by id (the plugin ABI's identity), each id holding its per-dataset **bindings** (`recipes_`: id → `GeneratorBindings`; an `all_datasets`/ephemeral recipe has exactly one), so a dataset-bound rule applied on a second dataset adds a binding rather than replacing, re-applied on the same dataset replaces that binding, and `generatorIds()`/`firstBinding(id)` serve the ABI's `list`/`config` (config reports the first-applied binding). An id's `ephemeral`/`history_exempt` flags are **homogeneous** across its bindings (`upsertGenerator` rejects a binding that would disagree with a surviving sibling), and a recipe whose `all_datasets` differs from the id's bindings **replaces the whole id** (old bindings and outputs retired) — so no id ever owns both a Dataset-scope and a Global output. A merge (`remapGeneratorsToAnchor`) rebinds consumed bindings onto the anchor; when the anchor already holds its own binding of that id, the anchor's wins (`mergeMarkerTopics`, which runs first, already moved every source marker topic onto the anchor's same-named topic — shifted by `raw_shift_ns` and concatenated after the anchor's set — so per-owner topics carry through one by one). `publishedMarkerScopes(store, dataset)` (`MarkerTopics.h`) reports which `MarkerScope`s have a marker object topic on a dataset (read from the ObjectStore, so unowned toolbox writes and tombstones count) — the query `pj_plotting`'s `PlotWidget::markerScopeRows()` is built from. Scope says where markers are drawn, not where the script runs: an `all_datasets` recipe reads from every loaded dataset that carries its inputs, and the union of those runs is one shared set published **once, on `kAllDatasetsMarkerDataset` (dataset id 0, a session-level home the store does not tie to a live dataset), in the display frame** (each contributor's run shifted by its alignment offset, `setDisplayOffsetResolver`) — the overlay draws it on every plot at the same display instant, so a Source Timeline drag republishes nothing; a change on any contributor re-runs the whole union, and **dataset lifecycle reconciles it**: `reachNewDatasets()` (called by `SessionManager::publishSharedMarkersToNewDatasets`, wired to `CatalogModel::itemsAdded` — the commit recompute runs before the catalog rebuild, so it can never see a new dataset) marks every all-datasets rule stale on every catalog addition — the catalog grows topic by topic, so a listed dataset may only now expose the series, and the brake turns a burst of additions into one run — and `clearGeneratorsForDataset(dataset)` (from `SessionManager::removeDataset`) rebuilds every shared set from the surviving contributors, tombstoning it when none is left (the rule stays live; every recompute of an existing all-datasets rule empties it the same way, only the initial upsert fails). `RefillGuard::rollback` re-runs the generators over the restored data, since the shared set lives outside the dataset's snapshot. `upsertGenerator` returns the generator's own (physical) object topic, and refuses an empty id, `#` in ids and output keys, and an id or output key that is not UTF-8 (the topic's metadata is JSON); a publish onto an existing topic that describes another marker set (scope, target, owner) fails and leaves that topic untouched, and `mergeMarkerTopics` leaves a source topic alone when its same-named anchor topic describes another set; `removeGenerator` retires every marker topic whose owner metadata is `<id>` (a merge moves a consumed binding's output onto the anchor and drops the binding, so the recipe alone cannot name it). | **History + declared names:** `GeneratorRecipe::history_exempt` keeps a generator outside undo/redo authority — `clearGenerators(RestoreIntent, keep)` (`clearAllGenerators()` = `kReplace`) retires each id once across all its dataset bindings except the ids in `keep` and, under `kHistory`, leaves exempt generators live; `unchangedGeneratorIds(wanted, intent, removed_upstream)` is that keep set: per id, every persistent binding equals the snapshot's binding on the same dataset on each persisted field (script and params ignoring line endings), the id is within the intent's authority, reads no series rooted at a name in `removed_upstream` (the outputs the restore removes or creates), and, for an `all_datasets` rule, it has published, has no run in flight (that run staged under offsets the restore may have moved back) and no contributor's display offset moved since its last published run (`publishRun` records the shifts of a run per `all_datasets` binding); a kept id keeps its topic, published entry, run state and coverage. `removeEphemerals(ids)` removes the listed previews still present and still ephemeral (the ones a `MarkersRuntimeHost` created, under `ownerPrefix(plugin)` = `"<plugin>/"`) and reports whether any went; `persistentBindingCount()` is `recipes().size()` without the copies; `hasHistoryExemptGenerators()` + `exemptDependentsOf(removed_inputs)` gate the history-restore preflight. One rule decides whether a rule reads a changed or removed name, for `recomputeForChangedInputs`, `exemptDependentsOf` and `unchangedGeneratorIds`: a series key rooted at the topic, itself or a field below a slash (`seriesKeyBelongsToTopic`, `src/SeriesKey.h`; `imu` is not `imu_raw`). `GeneratorRecipe::declared_inputs` (parallel to `inputs`, or empty; a length mismatch is rejected by `upsertGenerator`) carries the plugin's spelling of each input so the script enumerates/reads it under `series("src:key")` — see `DatasetQualifiedName.h` for the scope=all qualifier rejection and the config read-back policy. |
| `EnginePool.h` | Bounded low-priority worker pool for the derived-data engines: `submit(Task, Lane)` returns a `CancelToken`; `compute` runs on a worker, `publish(Outcome)` on the GUI thread in drains of at most 32 (`kCompleted`/`kCancelled`/`kFailed`: a throwing compute fails its run only). Runs ready tasks only; per-node queuing is the consumer's. See the header and `docs/derived_objects/ARCHITECTURE.md` §11. `SessionManager` owns the session's pool; `BatchEngine` runs on it. |
| `ObjectIngestTap.h` | Session-scoped exclusive consumers for builtin object bytes. Runtime hosts invoke a claimed kind synchronously after scalar parsing and before ObjectStore registration; the payload view is call-lifetime only. `SessionManager` owns the shared registry used by file, streaming, and delegated toolbox ingest. |
| `MarkerTopics.h` | Marker-topic vocabulary and queries. **Metadata is the identity; names are opaque ids.** `isMarkerTopic(descriptor)` (`pj_derived == "markers"`), `scanMarkerTopics(store, dataset)` (one pass, direct writes first), `markerTopicsOf(topics, request)` and `publishedMarkerScopes` read the metadata; `markerInfoForKey` turns the host's key vocabulary (`__global__` dataset scope, `__all__` all-datasets scope, otherwise a series key) into the scope and target; `markerOwnerTopicName` still mints the names. Nothing here parses a stored topic's name: a direct write to a 0.35 `__markers__/<key>` name is stamped with its metadata by `ObjectStore` on registration. A catalog and a dataset merge test `isMarkerTopic`; the time-bounds scans and the refill prune test `isOffClockTopic` (`DerivedTopics.h`), which also takes derived topics. |
| `DerivedTopics.h` | What an on-demand derived object topic is registered with and how it is recognized: `derivedTopicMetadata(type)` (the builtin type, `pj_derived: "on_demand"` from the SDK's `kDerivedMetadataKey` / `kDerivedOnDemandValue`, and `pj_snapshot` for SceneEntities and ImageAnnotations, D27; byte-stable so `findOrRegisterTopic` refills reuse the topic) and `isDerivedObjectTopic(descriptor)` (parses the metadata, never the name). `pj_derived` also takes `"markers"` on a marker topic, which this predicate rejects. `isOffClockTopic(descriptor)` (a marker or a derived topic) is what the time-bounds scans (`AppSession`'s playback focus, `SessionManager::datasetRawBounds`) and the refill prune skip: a marker set sits at 0 and a finding at `kFindingTimestamp`, and the host, not the file, writes both. |
| `RecipeGraph.h` | The on-demand recipes and their DAG, pure logic (no Qt, no store, no script runs): validation, binding every input in one dataset through an injected `InputResolver` (D7), upstream edges named by key (a removed upstream leaves its readers installed, `missingInput` says why), previews owned per plugin instance, pinned findings under a per-owner cap, and the restore protocol verbs (`unchangedRecipeKeys`, `clearRecipes`, `exemptDependentsOf`). A node's revision is graph-wide and changes only with its meaning. Contract: the header; design: `docs/derived_objects/ARCHITECTURE.md` §8, §13. |
| `ResultHistory.h` | Where the on-demand results live (no Qt, no threads, GUI thread only): each node's object outputs as derived topics in the `ObjectStore` (the ring, written in one `pushOwnedBundle` per result, with tombstones for unavailable outputs, a dedup ledger checked with `at(id, uid)`, and findings at `kFindingTimestamp`) and its decoded bundles (the compute cache). Both keep a window around the node's cursor (its last request, `noteRequest`; a late publication never moves it) and one global byte budget (256 MiB each by default) that evicts the result farthest from its node's cursor and never refuses; each node's displayed result and findings are never evicted, and `protectedExcessBytes()` is what is left past the budget after a pass. `lookup` (by the request's stamp) answers a cache hit, "stored" (the ring shows it, nothing to compute) or a miss; the cache keeps no decoded copy of a result the ring holds. The scheduler's surface (`resultAt` for a downstream input, `shownAt`, `supersedeTombstones`, `clear`, prepared payloads and cache-only results) and the transactional `install` are in the header, which owns the contract; design: `docs/derived_objects/ARCHITECTURE.md` §9, §10. |
| `MarkersRuntimeHost.h` | Host-side bridge that exposes the kind="markers" path of the unified **`pj.data_processors.v1`** SDK service to a plugin and delegates to `BatchEngine` — the markers sibling of `ToolboxRuntimeHost`. Accepts only `kind=markers` (`"transform"` is routed to the IncrementalEngine bridge owned by the transform-editor work). Implements the C-ABI vtable (per-plugin id namespacing, `"<plugin>/<id>"`), constructed per plugin binding by `DerivedRuntimeHosts`. `config` adds two keys older plugins ignore: `computing` (a run is in flight) and `error` (only when the last run failed). Not movable (the vtable stores `this`); the generators it creates outlive it (the host owns the runtime), except its previews (`previews()`), which `DerivedRuntimeHosts` ends with the plugin instance. |
| `CatalogModel.h` | Catalog of curves, objects, and data sources available to the UI. Also carries the demand-subscription surface: advertised-but-unsubscribed placeholders (`setAdvertisedTopics`, data-less rows real data supersedes) and the per-dataset `setPerTopicPauseCapable`/`isPerTopicPauseCapable` flag (set by `StreamingSourceManager` at session start/stop) that gates every demand-driven UI affordance — dimming, census previews, the force-streaming menu — so file datasets and non-demand sources are never misrepresented as pausable. **Identity facade:** re-exposes the session's dataset-identity surface for layout/plot binding (`datasetSourceName` — the raw `DatasetInfo::source_name`, not the deduped display label; `resolveDatasetIdentity`; `datasetSourcePath`), so widget code needs no separate `FileLoader` dependency. `findScalarForMarkerKey(dataset, key)` is the marker-input lookup behind `AppSession`'s batch resolver: it walks the items in place (no `items()` copy and sort), dataset first. `resolveCurveKey(saved_id, saved_source, saved_path, topic, field, capability)` (or `resolveCurveKey(SavedSeriesPath, capability)` for an identity held as one value) is the shared three-tier curve resolver both layout/undo restore (`PendingDisplayBinder`) and clipboard paste (`PlotWidget`) call, so the exact-id / unique-full-path / unique-source / reject-ambiguity algorithm lives in one place; its `SeriesCapability` parameter filters matches by consumer family (`kPlottable` for plot curves — the default — vs `kDiscrete` for State Transitions rows), backed by the `ScalarFieldPayload::logical_type` primitive and the `isPlottablePrimitive`/`isDiscreteField` predicates (integers/bool satisfy both; floats plot-only unless `ScalarFieldPayload::whole_numbers_only` — every retained value a whole number per `TopicStorage::wholeNumbersOnly`, e.g. JSON integers parsed as double — which also makes them discrete; strings discrete-only). | `HttpGet.h` | `httpGetWithTimeout()` / `httpPostWithTimeout()` — the one-shot async request idiom shared by `UpdateChecker`, `TelemetryPing`, and `pj_app`'s Preferences registry-URL reachability probe: caller-configured `QNetworkRequest` (the POST variant adds a body; set Content-Type yourself), transfer timeout, callback with the finished reply on the caller's thread (fires on error/abort/timeout too), reply `deleteLater`'d after the callback returns (callers must not retain it). Returns the in-flight reply so supersede/abort patterns work. |
| `TelemetryPing.h` | Fire-and-forget POST of the anonymous launch-ping payload to app.plotjuggler.io (a `httpPostWithTimeout`, default SSL verification, 15 s timeout). The payload is built internally in `TelemetryPing.cpp` — the privacy contract (environment facts only, salted-hash user id, PJ3-compatible keys) is enforced on the wire by `telemetry_ping_test`'s allowed-key set; extending the payload means updating that test + `docs/TELEMETRY.md` together. Emits `finished(ok)` once per send; the reply body is ignored, nothing is ever surfaced to the user, and all failures are silent. An unstamped `installation` never reports: `"source"` (the `PJ_INSTALLATION` default carried by every self-built tree — developers, CI, automation; matched trimmed and case-insensitively) and an empty stamp send nothing and report `finished(false)`, so no call site can leak a developer build to the endpoint. Any other stamp is sent as-is, so a downstream packager's own channel name still reaches the dashboard. The shell owns the user-facing opt-out (`Preferences::send_anonymous_stats`) and the automation guards. |
| `UpdateChecker.h` | One-shot "new release available?" check, asked of the channel that would deliver it (`setInstallation()` takes the `PJ_INSTALLATION` stamp): `deb` runs `apt-cache policy plotjuggler4` (candidate ≠ installed, repository present), `windows` runs the installed `maintenancetool check-updates`, anything else GETs GitHub's `releases/latest`. A `.deb` installed without the repository, or a Windows build without a maintenance tool, falls back to GitHub. `ReleaseInfo::route` (`Download` / `AptUpgrade` / `AptAddRepository` / `MaintenanceTool`) tells the shell what to offer. Emits **at most one** of `updateAvailable(ReleaseInfo)` / `upToDate()` / `checkFailed(reason)` (a superseded check emits nothing); every failure (network, HTTP 404, bad JSON, a probe that cannot run or times out) routes to `checkFailed`, so the shell can stay silent on the startup path. Probes need `QT_CONFIG(process)`; WebAssembly always asks GitHub. Widget-free — the shell wires `updateAvailable` to a toast. |
| `UpdateVersion.h` | Header-only version math behind `UpdateChecker`: `versionToComparable()` (tolerates a `v` prefix, `-rc`/`+build` suffixes, missing components; `-1` on garbage) and `isNewerVersion(candidate, current)` (strict, false unless both parse). Radix leaves room for a 3-digit minor (our beta is `3.999.0`). Unit-tested in `tests/update_version_test.cpp`. |
| `RecordingTypes.h` | Value types of a session recording: `RecordedBinding` (one delegated-ingest parser binding, captured verbatim so replay re-parses from the same inputs — the sink's owning form of the `RecordedBindingView` the tap receives, carrying no source identity, since one recording holds exactly one source), `RecordingInfo` / `RecordingSummary` (the start and final facts written into the file — the info names the capture the file belongs to (`capture_id`, `capture_ordinal`) and the source it recorded; the summary keeps `terminal_cause` (why it ended: stopped / source_ended / truncated / shutdown), keeps `truncated` separate from `file_incomplete`, since a truncated recording still closes into a complete file, and carries the `dropped_messages` the byte budget shed), `RecordingStats` (the same counters live, for the status label), and `TapVerdict` (a drop is NOT a verdict: the tap stays attached). |
| `RecordTap.h` | Observer of one source's delegated ingest, invoked inline on that source's push thread by `DataSourceRuntimeHost`: ONE call per `pushMessage`, before the parser runs, carrying the binding id, a non-owning `RecordedBindingView` of that binding (valid only for the call), the log time and the raw bytes. A tap that has not seen the binding id before creates whatever it needs from the view, so there is no separate announcement and "unknown binding" is not a reachable state. Implementations must not parse or touch datastore state; returning `kStopRecording` makes the host drop the tap. |
| `RecordingSink.h` | Where a `Recorder` writes: `open` → any mix of `addChannel`/`write` → `close`, strictly sequenced but not all on one thread — `open`/`close` run on the threads that start and stop the recording (the latter after the writer joined), everything between them on the writer thread, and the recorder's thread start/join order the handoffs, so a sink needs no locking of its own. The seam that keeps the recorder itself free of any file format. |
| `Recorder.h` | The recording engine joining `RecordTap` to `RecordingSink`, ONE per recorded source: `tapFor()` hands that source's `DataSourceRuntimeHost` a stateless tap that only co-owns the recorder and forwards; the recorder opens a channel from the first message it sees on a binding id (that host's binding ids are per source, so the binding→channel table is the recorder's, under its ONE mutex `mu_` — there are no atomics), while ONE writer thread drains a byte-budgeted queue into the sink — so plugin push threads never touch the file format and the sink sees a single strictly ordered caller. The default live policy is design decision **D4**: a producer never waits. When a message does not fit `RecorderOptions::queue_budget_bytes`, the largest member of {queued messages, incoming message} is discarded until it does — so the biggest queued message is evicted, or the incoming one is dropped when nothing queued is bigger, and a message larger than the whole budget is never recorded at all. Drops are counted (`RecordingStats`/`RecordingSummary::dropped_messages`) and leave holes, never reorderings: the survivors still drain FIFO. A slow writer therefore costs fidelity, never ingest speed, and never ends a live recording. Downloads may opt into `RecorderOptions::OverflowPolicy::kBlock`: producers wait for budget refunds and admit an oversized message only when no other message is queued or being copied. `requestStop()` ends admission and wakes those producers without waiting for the sink; cancellation must call it before joining producers, then call `stop()` to drain and close. Sink failures also wake waiters. A clean recorder summary is not proof of complete source coverage; the capture owner must gate publication on uncancelled, successful source completion. Truncation is reserved for failures: a sink `write` error truncates with the sink's own message and the rest of the queue is discarded without another sink call (an `addChannel` error truncates but still drains, since the sink itself is healthy); a `close()` that then also fails additionally sets `RecordingSummary::file_incomplete` (the file has no footer and needs `mcap recover`). `stop(terminal_cause)` carries WHY the recording ended into the summary the sink writes, before the close — a truncation overrides whatever was requested, since that is the cause a reader has to believe, and the destructor stops with `shutdown`. Must be owned by a `std::shared_ptr` — `tapFor` hands each tap co-ownership (it calls `shared_from_this()`, so a plain stack instance throws `std::bad_weak_ptr`), which is what keeps a push thread already inside `onMessage` from meeting a destroyed recorder. A truncation does **not** close the sink: the writer thread exits, the file stays open, and no summary exists until the owner — which polls `state()` — calls `stop()` anyway. `stop()` drains, **joins**, then closes, in that order, and is idempotent: later calls — a concurrent one included, which waits for the first to publish — return the same summary without touching the sink again. Failure containment is total: a sink `open()` that throws is a returned error and a `close()` that throws is an `incomplete` summary, a tap call or a sink call that THROWS mid-recording truncates it (the writer thread is `noexcept`; an exception escaping it would otherwise `std::terminate`), the failure transitions themselves allocate nothing before flipping state, and a `start()` that cannot spawn the writer closes the sink into a complete, truncated file rather than abandoning a footer-less one. Format-agnostic (links no mcap) and Qt-free (`recorder_test` compiles `Recorder.cpp` directly against `plotjuggler_sdk::base`, which is what lets it run in the TSan job), so it compiles for wasm too. |
| `RecordingFormat.h` | The on-disk contract of a recorded MCAP file — the `pj.recording` metadata record name, the terminal-cause tokens written into it, and the format version. Channels carry no PJ metadata: a recording holds one source, so its identity is a file-level fact. Shared with the `data_load_mcap` replay path, so changing a name here is a file-format break. |
| `McapRecordingWriter.h` | The `RecordingSink` implementation over `mcap::McapWriter`: one channel per binding (no channel metadata — the source identity lives once in `pj.recording`), schemas deduplicated by signature, 1 MiB zstd chunks — shared by small messages, while a message of 200 KiB or more gets a chunk to itself so a lazy reader never decompresses a video frame to reach a scalar sample — and a checked exclusive-create file sink that surfaces disk failures instead of silently truncating. `close()` fsyncs before it fcloses, so an ok Status means the bytes are on stable storage by the time the user is told the recording ended. `addChannel` refuses past 65535 channels or schemas — MCAP ids are `uint16_t` — so the recording truncates with a reason instead of wrapping ids onto live records. Desktop-only — not compiled for wasm. |
| `RecordingService.h` | GUI-thread owner of at most ONE active capture, and the seam `pj_app`'s Record action drives. One Record press = one batch folder `pj_<UTC yyyyMMdd_HHmmss>/` (created with a bare `mkdir`, so creating it IS claiming it) holding ONE file per recorded source, named `<sanitized display name>.mcap` (NFC-normalised, reserved characters and separator runs folded to `_`, cut to 80 characters, `_2`/`_3` ordinals on a case-folded collision, the writer's exclusive create as the last guard). Each source gets its own `Recorder`, writer thread and queue budget, and every file of the press carries the same `capture_id`. Resolves the recordings folder and the queue budget (`QSettings` keys `Preferences::recording_directory` / `Preferences::recording_queue_budget_mib`; empty directory = `<AppLocalDataLocation>/recordings`; the budget is clamped on load to the Preferences range 8..4096 MiB, and is PER SOURCE, so N sources may hold N times it). `start()` is transactional: it opens every file before attaching any tap, and any failure detaches every target it touched, closes and deletes every file it created, removes the folder if it empties, and emits no `started`. Each `RecordingTarget` describes one source by an opaque `target_key` (pj_app passes the `DatasetId`) plus callbacks (`attach`, which returns false when the source vanished and which a null tap turns into a detach, and `skipped_lazy`), so the service never learns about `DataSourceRuntimeHost`; eligibility is the caller's call, and `pj_app`'s streaming manager filters on `kCapabilityDelegatedIngest` (D1: a direct writer has no raw bytes at the seam) and names the excluded sources beside the targets. Finalization is SYNCHRONOUS on the GUI thread and happens exactly once per recorder: `stop()`, `onSourceEnded(target_key, reason)` (which finalizes ONE source and leaves the rest recording), a poll-detected truncation and the destructor all detach the tap, freeze the source's pure-lazy delta and close that file. A 500 ms poll publishes `progress()` over the live recorders plus the frozen totals of the finished ones, so the totals never decrease; per-source problems are logged, not signalled. `stopped(CaptureResult)` fires once per press once every source has its result: per source a path, a `terminal_cause` and ONE exclusive outcome bucket — `incomplete` (unfinalized: needs `mcap recover`) beats `truncated` (a failure ended the data) beats `lossy` (holes: drops, pure-lazy skips, or a source that ended with a reason) beats `clean` — plus the capture totals, so callers test `clean_count`, never a boolean. Built on every platform (Qt Core + `<filesystem>`, no mcap); only the sink it defaults to is platform-bound, so `isSupported()` is the single runtime query the shell gates its Record UI on, and `start()` fails with `recording is not available in this build` — before touching the filesystem — where no sink was compiled in and no test injected one through `setSinkFactoryForTest`. |

## Linked dependencies

Public link surface (per `CMakeLists.txt`): `Qt6::Core`, `Qt6::Network`, `Qt6::Xml`, `pj_datastore`, `pj_tf` (the Qt-free TF-buffer leaf: `TransformService.h` exposes `pj::tf::TransformBuffer` and `pj::tf::TransformSnapshot` in its public API, and `glm::glm` reaches `pj_runtime` transitively through this link), `pj_marketplace`, the SDK discovery primitives (`pj_data_source_host`, `pj_message_parser_host`, `pj_toolbox_host`, `pj_plugin_catalog`, `pj_base`), `nlohmann_json`. `pj_scripting` is public too: `RecipeGraph.h` exposes `scripting::OutputSpec` and `ResultHistory.h` `scripting::ScriptBundle` (and DataProcessorService routes by-id applyFilter through the Luau FilterCatalogue; BatchEngine runs whole-series rules through `runMarkerScript`). Private: `tsl::robin_map`, `pj_internal_fmt`.

The `pj_marketplace` link is conditional: `$<$<NOT:$<BOOL:${EMSCRIPTEN}>>:pj_marketplace>` in `pj_runtime/CMakeLists.txt` links it only on non-wasm builds. On `EMSCRIPTEN`, `pj_runtime` instead adds `pj_marketplace/include` as a private include directory (so `DiagnosticHistory`'s lightweight `QtDiagnosticBridge` type still compiles) without linking the rest of the marketplace module.

`mcap::mcap` is private and conditional in the same way (`$<$<NOT:$<BOOL:${EMSCRIPTEN}>>:mcap::mcap>`): only the recording **sink** is platform-bound, so `find_package(mcap)`, the `McapRecordingWriter` sources and the tests that read an MCAP back are inside `if(NOT EMSCRIPTEN)`. `RecordingService`, `Recorder` and the recording interface headers are built unconditionally; `RecordingService::isSupported()` reports whether this build got a sink, and `pj_app` gates its Record UI on that alone (no compile definition is exported).

## When porting from PJ3

PJ3 wiring into `PlotDataMapRef` / `TransformsMap` becomes wiring into the services above — primarily `CatalogModel`, `SessionManager`, `PlaybackEngine`, and (future) `TransformRegistry`. This is the **one systematic rewrite** during a PJ3 port; everything else should be lifted close to verbatim.

## Tests

`tests/` — gtest-based, with service suites linked into `pj_runtime_tests` using the shared `QCoreApplication` main. `gtest_discover_tests` registers each case as `pj_runtime_tests.<suite>.<case>` and runs it in its own process. Add test sources to `PJ_RUNTIME_TEST_SOURCES` alongside any new service; mock plugin fixtures remain shared-library targets with their paths supplied to the runner.

`tests/engine_freeze_bench_test.cpp` (`EngineFreezeBench.*`) prints how long the GUI thread stalls when a transform or a marker rule is applied over a 500k-row series, or a rule re-runs after an input change, until the result is complete (the marker creates are split into staging alone, a trivial threshold rule and the heavy rule; the re-run and those two read through the resolver `AppSession` installs): GUI-thread CPU time (the longest single stretch, the call or one event-loop pass, and the total) and the worst wall-clock stall (lateness of a 1 ms heartbeat timer, which also sees lock waits and preemption), medians of five applications. It is skipped unless `PJ_BENCH` is set; the baselines are in `docs/derived_objects/ARCHITECTURE.md` §19.

`recorder_test` stays a separate, Qt-free executable for the TSan target list, with its existing 60-second timeout. `transform_service_test` is a separate executable with a custom `QCoreApplication` main: its debug thread-affinity death test forks and deliberately aborts in the child process. `extension_catalog_service_thread_safety_test` also keeps its dedicated target and CTest name for focused concurrency runs. To select the whole module in a configured test tree, use `ctest -R '^(pj_runtime_tests\.|recorder_test$|transform_service_test$|extension_catalog_service_thread_safety_test$)'` inside the builder image.

`tests/on_demand_test_utils.h` (point clouds, recipes whose scripts never run, store readers) is shared by the on-demand tests.

`tests/recording_test_utils.h` (the `pj.recording` metadata lookup + the `IsolatedQtSettings` QSettings/QStandardPaths sandbox) and `tests/runtime_host_test_fixture.h` (a real `DataSourceRuntimeHost` over the hermetic catalog and the mock object parser) are shared by the **recording** tests only. The pre-existing host tests (`data_source_runtime_host_object_ingest_test`, `..._stream_swap_test`) are deliberately left on their own fixtures: folding them in would be a large unrelated diff on tests that are not changing.

`tests/recording_pipeline_test.cpp` joins the runtime runner on desktop builds and assembles the whole recording pipeline — real `DataSourceRuntimeHost`s over a hermetic catalog and a real parser plugin → `RecordTap` → `Recorder` → `McapRecordingWriter`, driven by `RecordingService` — and reads the produced files back with `mcap::McapReader`. It covers what no single seam's unit test can see: that a recording started mid-stream captures topics bound before it, that pre-recording pushes never leak in, that two live sources land in two files of one capture (same `capture_id`, ordinals 1 and 2, each holding only its own topics), that a second recording starts from an empty channel table, and that ingest is unaffected either way.
