# pj_runtime

## Purpose

App runtime services and contracts for PlotJuggler 4. This is the **services seam** between the shell (`pj_app`) and the rest of the system: every widget family (`pj_plotting`, `pj_scene2D/widgets`, `pj_scene3D/widgets`) reads from and reacts to services exposed here, but the widget families themselves are siblings and never depend on each other.

## Hard constraints (from root CLAUDE.md)

- Qt is allowed (`Qt6::Core`, `Qt6::Network`, `Qt6::Xml`).
- **`Qt6::Widgets` is forbidden.** No concrete widgets live here. Anything that needs `QWidget` belongs in `pj_widgets` or a widget-family module.
- Public headers under `include/pj_runtime/` are the SDK boundary for the shell and widget modules.

## Public surface

The authoritative source is `include/pj_runtime/`. Today:

| Header | Role |
|---|---|
| `AppSession.h` | Central runtime object. Owns and exposes the services below, including `topicDemandTracker()` (the demand-driven per-topic streaming subscription tracker — see `TopicDemandTracker.h`). `pj_app` instantiates one at startup. **Source Timeline additions:** `datasetRawTimeRange(DatasetId)` returns the raw `[min,max]` absolute-ns bounds across a dataset's catalog-visible topics (used by `SourceTimelineController` to populate bar extents); `recomputeRange()` updates only the `PlaybackEngine` range from the offset-adjusted union of visible topics (called throttled on the drag path — never resets `currentTime` while data remains) and returns that union's display-min, which `seedPlaybackFromSession()` reuses for the first-load playhead snap (one scan, not two); when NO visible data remains it instead collapses the transport to the empty state via `resetPlaybackToEmpty()` (pause, `[0,0]` range, cursor 0), the same reset the `CatalogModel::cleared()` hook runs on a full wipe — this is what stops playback and resets the slider when the last dataset is removed. Both are implemented via a shared `forEachVisibleRawRange` private scan so visibility/dedup rules live in one place. `mergeDatasets(selected)` **destructively** folds the selected datasets into one (the OR/union): the anchor = leftmost-in-display dataset keeps its clock + ids, the others are shifted into it by their relative display offset and removed from the catalog, scalar topics union by name, object topics fuse by name, and the anchor is relabelled `*_merged` (returns the anchor id). `AppSession::objectMergeConflicts(selected)` is the canonical builtin-object-type preflight; on successful merge AppSession emits `datasetsMerged(anchor, consumed)`. |
| `SessionManager.h` | Session lifecycle (load/clear/active dataset). Also owns and exposes the session's `CurveColorRegistry` so plot widgets can reach it through their existing `SessionManager` pointer. `displayTimeForSource(DatasetId, absolute_ns)` maps a raw instant onto the display axis under that dataset's current `displayOffset` (nullopt for an unknown dataset) — the `pj.playback.v1` conversion slot. **Source Timeline additions:** `setDisplayOffset(DatasetId, DisplayOffset)` writes a per-source display shift to the underlying `TimeDomain` and emits the per-dataset `displayOffsetChanged(DatasetId)` — idempotent, so an unchanged offset emits nothing (no spurious replot/rebuild); it is consumed by `PlotWidget` (drops that dataset's adapter offset cache, refreshes the max zoom-out extent + magnifier limits, and replots at current zoom) and by `SourceTimelineController` (refreshes the bar offsets + triggers throttled `recomputeRange`). This per-source signal is **overloaded against** the no-arg `displayOffsetChanged()` that the global "Use time offset" frame (`setUseTimeOffset`) emits — connect either with `qOverload<>` / `qOverload<PJ::DatasetId>`. **Time-offset model (decoupled):** the total `displayOffset(id)` that everything on the display axis reads (plot curves, scenes, playback range/cursor) = the per-source *alignment* shift (`sourceDisplayOffset(id)`, the TimeDomain offset the Source Timeline edits) **plus** a single global `globalTimeReference()` (the earliest raw sample across all datasets when "Use time offset" is on, else 0 — applied **uniformly** so cross-dataset time gaps are preserved, not a per-source rebase). `setUseTimeOffset` flips *only* the global reference and never writes per-source offsets, so toggling never disturbs the Timeline's bar positions. The Source Timeline reads `sourceDisplayOffset` for its bars (align-only frame) and the host (`SourceTimelineController`) bridges `globalTimeReference` across the playback↔timeline frame gap. **Dataset removal:** `removeDataset(DatasetId)` is the seam for a real delete — it erases the dataset's scalar storage from the `DataEngine` AND invalidates the time-origin caches (`globalTimeReference()` re-bases to the survivors), so callers must use it rather than reaching into `dataEngine().removeDataset` directly (which would leave the memoized earliest-sample origin stale when the earliest dataset is removed); when that re-base actually moves the origin it emits `displayOffsetChanged()` so surviving curve adapters drop their now-stale offsets and re-fit; it also drops the dataset's source-path registry entry. **Dataset identity registry:** owns the `DatasetId` → normalized-full-path map (`setDatasetSourcePath`/`datasetSourcePath`, written by `pj_app`'s `FileLoader` — `DatasetInfo::source_name` is only a display label and cannot distinguish same-basename files) and `resolveDatasetIdentity(id, source, path)`, which resolves a persisted identity without ever guessing by load order: exact live id (trusted only while the saved qualifiers still agree) → unique full-path match → unique source-name match → reject with `DatasetIdentityResolution::ambiguous` (nullopt id + `ambiguous=false` = not loaded yet). `resolveObjectDatasetIdentity` adds an object-topic-name tiebreak for same-file fan-out siblings. **Token-addressed progressive ingest:** manages a dataset's load stream via `IngestToken` (`quint64`-addressed; 0 = invalid). `beginIngest(DatasetId, label, total, cancellable, cancel_fn)` starts a stream; **a new `beginIngest` on a dataset supersedes any prior token**, invalidating the old token's pending `updateIngest`/`endIngest`/`requestCancel` calls (they become silent no-ops) and **reporting the superseded run's terminal as `ingestEnded(old_token, kCancelled)`** before the new `ingestBegan` — so no observer has to infer a supersede from the next began, or leak what it bound to the old token. At most ONE ingest per dataset is tracked (the dataset IS the identity; the entry carries its token id), and the single `liveEntry(token)` lookup is the one definition of token staleness. `updateIngest(token, current, total)` publishes that dataset's flushed topics **before the staleness gate** — preventing a publish-ordering slip from ever dropping data — and reports `ingestProgressed` **factually**, including after a stop was requested (the producer keeps delivering until it notices): freezing a stopping row's bar is presentation policy and lives in `IngestProgressController`, not here; `endIngest(token, outcome)` closes the stream. **Cancellation intent wins:** `requestCancel(token, keep_partial)` records cancellation intent, so whichever terminal (`endIngest` or a late `requestCancel`) arrives after intent **reports `kCancelled` regardless** of what the producer passed; a cancel after the terminal is refused. **`kUnknown` outcome exists** because the plugin C-ABI's `on_ingest_finished` carries no outcome code — reporting `kCompleted` would assert a success nobody observed. Observable surface: `ingestActive(DatasetId)` checks current status, `activeIngests()` snapshots the full set (label/current/total/cancellable state), signals `ingestBegan` / `ingestProgressed` / `ingestEnded` fire for shell binding. Paired view layer: `CurveTreeView` in `pj_widgets` renders per-dataset progress bars (row-spanning fill plus, on a cancellable row, TWO stop affordances — ✕ = stop and keep, bin = stop and discard — reported as `cancelRequested(row_key, keep_partial)`, so the host acts on the user's choice instead of prompting for it; honouring `keep_partial` is the producer's job); `IngestProgressController` in `pj_app` keys each row by its ingest id (the row key IS `IngestToken::id`, so a click resolves back to its ingest by lookup) and owns UI lifetime policy (1 s completion linger, ~180 ms error flash per `State::kFailed`, ghost rows for discarded loads, display-name feed, and the frozen bar of a `kStopping` row). Title-bar progress strip (`IngestProgressWidget`) is API-retained but suppressed via `constexpr kShowTitleBarIngestStrip=false` at its show seam. **Loader-metadata registry:** `setDatasetMetadata`/`datasetMetadata`/`clearDatasetMetadata` hold one loader-supplied JSON document per dataset (attributed to the emitting plugin; bounds in `validateDatasetMetadata` — object root, ≤1 MiB, depth ≤32, ≤16384 values; rejection keeps the previous document and never affects ingest) — the third sibling of the source-path/source-record registries with the same lifecycle: erased by `removeDataset`, invalidated for every contributor of a destructive merge, cleared by a committed refill (`RefillGuard::commit`). `FileLoader` publishes each load's staged document (`DataSourceRuntimeHost::stageLoaderMetadata`, fed by the SDK `set_dataset_metadata` slot) at the same commit seams that set source paths; `CatalogModel::datasetMetadata` is the read-only facade, and the curve tree's Info dialog renders the document generically. |
| `MarkerService.h` | Host service backing the unified **`pj.data_processors.v1`** SDK service for `kind=markers` — the **object engine**. Runs plugin-submitted **whole-series** generators via `pj_scripting`'s `runMarkerScript` and publishes the resulting `PlotMarkers` to the `ObjectStore` (`__markers__/…`). **Invariant: writes ONLY to the `ObjectStore`, never the `DataEngine`** — timeseries outputs come from transform generators (`kind=transform` → `DerivedEngine`), not here. Owned by `SessionManager` (`markerService()`); the shell injects a catalog-backed series resolver + dataset lister. Supports ephemeral previews (excluded from persistence) and global-across-all-datasets generators. Re-runs on commit/reload via `recomputeForChangedInputs`. (Class name kept; an `ObjectEngine` rename to admit object kinds beyond markers is a future cosmetic step.) |
| `ObjectIngestTap.h` | Session-scoped exclusive consumers for builtin object bytes. | `MarkersRuntimeHost.h` | Host-side bridge that exposes the kind="markers" path of the unified **`pj.data_processors.v1`** SDK service to a plugin and delegates to `MarkerService` — the markers sibling of `ToolboxRuntimeHost`. Accepts only `kind=markers` (`"transform"` is routed to the DerivedEngine bridge owned by the transform-editor work). Implements the C-ABI vtable (per-plugin id namespacing), constructed per toolbox bind in `MainWindow`. Not movable (the vtable stores `this`); the generators it creates outlive it (the host owns the runtime). |
| `CatalogModel.h` | Catalog of curves, objects, and data sources available to the UI. Also carries the demand-subscription surface: advertised-but-unsubscribed placeholders (`setAdvertisedTopics`, data-less rows real data supersedes) and the per-dataset `setPerTopicPauseCapable`/`isPerTopicPauseCapable` flag (set by `StreamingSourceManager` at session start/stop) that gates every demand-driven UI affordance — dimming, census previews, the force-streaming menu — so file datasets and non-demand sources are never misrepresented as pausable. **Identity facade:** re-exposes the session's dataset-identity surface for layout/plot binding (`datasetSourceName` — the raw `DatasetInfo::source_name`, not the deduped display label; `resolveDatasetIdentity`; `datasetSourcePath`), so widget code needs no separate `FileLoader` dependency. `resolveCurveKey(saved_id, saved_source, saved_path, topic, field, capability)` is the shared three-tier curve resolver both layout/undo restore (`PendingDisplayBinder::resolveSeriesPath`) and clipboard paste (`PlotWidget`) call, so the exact-id / unique-full-path / unique-source / reject-ambiguity algorithm lives in one place; its `SeriesCapability` parameter filters matches by consumer family (`kPlottable` for plot curves — the default — vs `kDiscrete` for State Transitions rows), backed by the `ScalarFieldPayload::logical_type` primitive and the `isPlottablePrimitive`/`isDiscretePrimitive` predicates (integers/bool satisfy both; floats plot-only; strings discrete-only). |
| `HistoryScope.h` | `SnapshotScope` (`kFull`/`kHistory`) and `RestoreIntent` (`kReplace`/`kHistory`): the vocabulary for what a capture includes and what authority a restore has over history-exempt state. Layered on the absolute spine (`Timepoint`/`Duration`/`fromRaw`/`toRaw`) in the SDK at `pj_base/time.hpp`, so every layer can name absolute time; the display coordinate stays here because the per-dataset offset is an app-presentation policy, not an SDK concern. |

| `DataSourceRuntimeHost.h` | Host-side runner for `DataSource` plugins from `pj_plugins`. Threads a **plugin-DSO keepalive** (`shared_ptr<void>` from `DataSourceHandle::libraryOwner()`) into every lazy payload anchor + fetch closure, deferring `dlclose` until the last anchor/parser drops — so a decode worker never calls plugin code (`release`/`parseObject`) in an unmapped `.so`. Pitfall: a plugin `release` may run on an arbitrary worker thread during/after teardown (see the header). Implements `notify_available_topics` (`cbNotifyAvailableTopics`): classifies each advertised topic a priori via `ExtensionCatalogService::classifyParserObjectRoute` (object route only; registry encodings answer from the routing service's cached classification records with no winner instantiated, other encodings classify on a throwaway instance — no `bind(registry)` needed either way); falls back to matching the type name against `FrameTransforms`/`CameraInfo` when neither yields a type and hands the classified set to the optional `on_available_topics` callback, which fires on the **poll/stream thread** — the callback owns marshaling to the GUI thread (`pj_app`'s `StreamingSourceManager` does this, feeding `CatalogModel::setAdvertisedTopics` + `TopicDemandTracker::setInfrastructureTopics`). `cbEnsureParserBinding` is **idempotent per request signature** (topic + encoding + type + schema + parser config): a demand-driven plugin re-requests its binding on every re-subscribe, and handing back the existing binding is what prevents a duplicate engine topic (`DataEngine::createTopic` mints a fresh TopicId per call, no name dedup) from doubling every field in the catalog; a changed signature (retyped topic) still mints a fresh binding, while a catalog reload alone never does (see `ParserRoutingService.h`). The scalar winner takes the binding and the object winner supplies the object classification + lazy re-decode instance, whichever selection mode produced them. Implements the SDK 0.30 completion contract: `attach_source_record` (bounded JSON descriptor, last-attach-before-first-push wins, attach-after-push or after-seal vetoes capture) and `complete_ingest` (validated via the SDK's `copyIngestCompletion`; seals the context — later pushes are rejected and latched; identical repeats idempotent; a conflicting or malformed terminal permanently vetoes). The host instance IS the ingest generation, and `sourceRecordDescriptor()` / `ingestCompletion()` / `captureVetoReason()` / `ingestCallbackFailures()` are the read-back surface `SourceCaptureService::finalize` gates on (every `fail()` is latched — a plugin may recover, but recorded bytes then disagree with the dataset). Exposes `setRecordTap()` for the session recorder: the tap is called inline on the push thread once per pushed message's raw bytes, before the parser runs, and each call carries a `RecordedBindingView` of that message's binding (topic + the signature's encoding/type/schema, non-owning and valid only for the call). Carrying the binding on every message rather than announcing it separately is what lets a recording started mid-stream capture topics subscribed long before it, with no per-binding bookkeeping in the host. A `kPureLazy` push fetches no bytes on that thread, so it is counted in `recordTapSkippedLazy()` instead of recorded. |
| `ToolboxRuntimeHost.h` | Host-side runner for `Toolbox` plugins: assembles `ToolboxHostService` (write surface) + `ToolboxRuntimeHostService` (diagnostics / data-changed) + `SettingsStoreService` into a `ServiceRegistry`. App concerns are injected as `Callbacks`; the `[thread-safe]` report/notify callbacks marshal onto the constructing (GUI) thread. With optional `ParserIngestDeps` (extension catalog + render-parser registrar), the `create_parser_ingest`/`release_parser_ingest` tail slots hand a toolbox-created dataset the standard `DataSourceRuntimeHost` delegated-ingest surface (one per dataset; release = flush + destroy, idempotent; driven from the toolbox worker thread, not GUI-marshalled). `on_data_changed` reports the bulk-import datasets so the shell can focus playback on them: contexts created/released since the previous notify (drained per notify) **plus** every context currently mid-import (between `progress_start` and `progress_finish` on the ingest fat pointer) — so a progressive import keeps its focus as it grows. The ingest fat pointer's progress slots also drive the progressive-import surface: each unthrottled `progress_update` (default 50 ms, `setFlushThrottleMs` test seam) flushes BOTH write surfaces (parser bindings + the toolbox write host) on the plugin's ingest thread, then fires the GUI-marshalled `on_ingest_started/progress/finished` callbacks — so a shell handler can treat every `on_ingest_progress` as "new rows are reader-visible" and publish incrementally (`pj_app` mirrors `FileLoader::publishIngestProgress`). Implements the formalized `discard_parser_ingest` (SDK 0.30): the rollback twin of release — the context is destroyed WITHOUT `flushAll()`, so pending parser rows die with their writers, and no completed-import marker reaches the shell. `requestStopActiveIngests()` is the shell's stop affordance: flag-only cooperative cancel every live context reports through `is_stop_requested` / `progress_update == false` (keep-partial semantics; the toolbox ABI has no host-side rollback). **M3 owner wiring:** with `ParserIngestDeps::capture_service` + `capture_provider_id` set, every fresh context is armed for source capture at creation; RELEASE is the commit (the `SourceCaptureService::finalize` gate runs on the release caller's thread, then the store's budget `cleanup()`), DISCARD and host teardown abort the capture, and a host-side stop makes finalize refuse. A record-worthy release (attached descriptor + clean COMPLETED, published or not) fires `on_capture_finalized` on that same thread with the descriptor, the `sourceCacheIdentityDigest` identity and the published artifact path, so the shell can attach the dataset's `SourceRecord` and register the artifact as its saveable backing file. |
| `DataProcessorService.h` | Applies "Data Processors" as eager `DerivedEngine` nodes. Two tiers of one substrate: **filters** (per-curve, hidden output, keyed by output topic) via `applyFilter`/`updateFilter`/`clearAllFilters`; **transforms** (named, plugin-owned, session-persisted, keyed `"<plugin>/<id>"`) via `upsertTransform`/`removeTransform`/`restoreTransform`/`transformRecipes`. Transform recipes capture dataset/source/topic/field input identity; replacing reloads use `rebindAndRecomputeForReplacedSources` to update semantic column bindings in place while preserving output TopicIds. Compatible script edits replace operators transactionally, structural edits reject before mutation, and removal cascades by exact TopicId. `sourceTopicsForOutput(TopicId)` walks mixed processor chains to their exact raw subscription topics. `TransformRecipe::history_exempt` (and, in `MarkerService.h`, `GeneratorRecipe::history_exempt`) marks a processor immune to undo/redo: persisted through a layout file like any other recipe, but never removed, recreated, or replayed by a history restore. `clearTransforms(RestoreIntent, keep_keys)` (`clearAllTransforms` is the `kReplace` wrapper; `keep_keys` lets a restore leave unchanged transforms live so their output TopicIds survive — `unchangedTransformKeys(wanted, intent)` computes that set by comparing each live recipe's persisted fields against the snapshot entry with the same key; binding-less legacy entries never match) and `hasHistoryExemptTransforms()` gate the history preflight; filters are never exempt, so `clearAllFilters` has no such switch. `liveNonExemptNodeIds(keep_keys)` and `liveNonExemptOutputNames(keep_keys)` describe what a history restore actually removes (every filter plus the non-exempt transforms outside `keep_keys` — the same exclusions as `clearTransforms`), while the transform and marker `exemptDependentsOf(...)` queries let a caller reject that restore before clearing anything. `pj_app`'s `MainWindow::restoreDataProcessors` is the caller (`RestoreIntent::kHistory` vs `kReplace`); see `pj_app/CLAUDE.md`. |
| `DatasetQualifiedName.h` | Uses the SDK's `sdk::splitDatasetQualifier` for catalog-dependent `dataset_source:topic/field` lookups: longest loaded prefix wins; unmatched prefixes stay part of the complete bare name. Colons in both parts can prevent round-tripping; this is not a persistent identity. `resolveMarkerDataset` validates dataset uniqueness, normalizes qualified keys to bare form, refuses a bare input found in several datasets (suggesting only the qualified forms that resolve back to that dataset), and rejects any input — qualified or not — that does not exist in the chosen dataset. `MarkersRuntimeHost` runs it only for single-dataset generators: under `{"scope":"all"}` keys are literal in every dataset and zero inputs are fine, so a key whose prefix names a loaded source is rejected there (a colon matching no source stays part of the key). When a qualifier was stripped the recipe keeps the declared names (`GeneratorRecipe::declared_inputs`, persisted in the layout as `<input declared=…>`) so the script enumerates and reads each series under `series("src:key")`. `uniqueDatasetForSource` is the shared source-name → dataset lookup (ambiguous when a source is loaded twice). Transforms use the same SDK splitter in `DataProcessorService::installTransform`, which rejects qualifiers naming two different datasets; a topic name duplicated inside one dataset is reported ambiguous. Config read-back (`data_processor_config`, for both kinds) echoes each input bare (markers: as declared) unless its bare name is ambiguous across the loaded datasets AND `dataset_source:bare` resolves back to the bound dataset — so a bare cross-dataset transform stays resubmittable and no emitted address resolves elsewhere; an input for which neither spelling round-trips echoes bare (unrepresentable). Names stay bare internally. |
| `DataProcessorsRuntimeHost.h` | Host-side bridge exposing the `pj.data_processors.v1` SDK service to ONE plugin over `DataProcessorService` (data-only; every id namespaced under the plugin; all slots `[main-thread]`, so no Qt / no marshalling). A created transform OUTLIVES the bridge — destroying it (DSO unload) leaves the node running; only an explicit `remove`/`clearTransformsForPlugin` tears it down. |
| `QSettingsBackend.h` | `sdk::SettingsBackend` implemented over `QSettings` (→ `PlotJuggler4.conf`); injected into `ToolboxRuntimeHost` so plugin settings persist. `'/'`-separated keys map to `.conf` groups. |
| `ExtensionCatalogService.h` | Marketplace-backed extension catalog (queries `pj_marketplace`). Composes the loaded plugin set via `PluginRuntimeCatalog` over the scan hierarchy `--plugin-dir` (authoritative) → custom Preferences folders (authoritative) → marketplace dir (managed). At construction (every mode) it **seeds** the bundled dir `<prefix>/lib/plotjuggler/plugins` into the default marketplace dir — copy when absent, staged refresh when the bundled version is newer, and never downgrade a compatible install; a copy the current host would reject for a malformed plugin version or under the shared ABI + `min_sdk_required` + `min_plotjuggler_version` gate (see `descriptorIncompatReason`) is rescued by overwriting it with the bundled build, since the bundled dir is never scanned as a load path and would otherwise leave the id dead. It hands the bundled id→version map to the `ExtensionManager` (core-plugin uninstall lock) in default sessions only; the bundled dir itself is never scanned. `Paths` constructor = test seam for all three roots. Lookups over the loaded set: `findSourcesForExtension`, `findParserByEncoding`, `findToolbox(id)` (raw pointers into the catalog vectors, GUI-thread only, valid until the next `reload()`). Browser/static builds skip the marketplace and register their application-composed `StaticPluginSet` before scanning. |
| `ParserRoutingService.h` | Route-aware parser selection over the SDK `ParserClaimCatalog` + `ParserRouteResolver`, owned by `ExtensionCatalogService`. For encodings in the SDK claim registry the **scalar** and **object** routes of one topic resolve independently: every loaded parser holds the wildcard scalar claim for its registered encodings; exact per-type claims are discovered lazily on first sight of a (provider, encoding, type, schema, config) via the `pj.parser_route_claims.v1` extension, or legacy `classify_schema` (object route only) when absent; candidates rank exact > wildcard, then host-derived provenance (`kBundled` needs id + version + DSO signature of the shipped build; `--plugin-dir`/custom folders are `kFolderDrop`; else `kMarketplace`), then priority. Every winner is an instance prepared (`bindSchema` + `loadConfig`) during the same resolution — probe instances are pooled per call and reused as the winner, and no instance is ever shared between two bindings; the resolver's probe cache retains only a small classification record, and a probe/classification error is evicted after each resolution so a transient provider fault retries instead of freezing as a decline. Encodings outside the registry (and non-normalizable type names) select the first provider registered for the encoding for both routes (`route_dispatch == false`), which is the parser the pre-routing host picked. The service is externally synchronized: `ExtensionCatalogService` serializes it under `routing_mutex_`, taken BEFORE `catalog_mutex_` (shared for resolve/classify, exclusive in `reload()`, which rebuilds the claims inside that section), so one resolution never mixes two catalog generations and queued resolutions never hold the catalog shared lock against a waiting GUI reload. `DataSourceRuntimeHost` consumes it: the scalar winner takes the binding, the object winner's classification governs object-topic registration and supplies the lazy re-decode instance, divergent winners leave the in-parse object sink unregistered, and an object topic records its first decoder provider so a later binding under another provider stays scalar-only (history is never re-decoded by a replacement). |
| `PluginRuntimeCatalog.h` | Host-side plugin catalog: scans the folder hierarchy via the SDK's `scanPluginDsos`, resolves duplicate ids by **authoritative → compatibility → version → folder priority**, then hard-rejects a winner with a malformed version or incompatible host contract before loading it through the SDK loader. An authoritative copy still shadows every managed same-id fallback, so a broken `--plugin-dir` build fails visibly instead of silently testing a different plugin. This resolution is host policy — it was relocated here from the SDK so the SDK stays a thin discovery/loader layer. `registerStaticPlugins(const StaticPluginSet&)` applies the same admission gate to plugins linked directly into the binary (data sources, message parsers, and toolboxes with optional companion dialog vtables), which is the WASM path when dynamic loading is unavailable. |

| `TopicDemandTracker.h` | Demand-driven per-topic streaming subscriptions: computes, per streaming dataset, the active set = displayed (ref-counted `addReference`/`removeReference(DatasetId, topic_name)`) ∪ infrastructure (`setInfrastructureTopics` — TF/CameraInfo) ∪ user-forced (`setTopicForced` — the curve-tree "Force topic streaming" context action; a tier, never an override, so unforcing cannot pause a displayed topic; `forcedTopicsChanged` fires even when the active set doesn't, for UI badging). Emits `activeTopicsChanged(dataset_id, sorted-unique names)` only on change. GUI-thread only; owned by `AppSession`. | `SourceCacheStore.h` | Host-side source cache (M3, RECORDING_AND_CACHING.md §3.4): one MCAP artifact per provider request identity. | `RecordingSink.h` | Where a `Recorder` writes: `open` → any mix of `addChannel`/`write` → `close`, strictly sequenced but not all on one thread — `open`/`close` run on the threads that start and stop the recording (the latter after the writer joined), everything between them on the writer thread, and the recorder's thread start/join order the handoffs, so a sink needs no locking of its own. The seam that keeps the recorder itself free of any file format. |
| `Recorder.h` | The recording engine joining `RecordTap` to `RecordingSink`, ONE per recorded source: `tapFor()` hands that source's `DataSourceRuntimeHost` a stateless tap that only co-owns the recorder and forwards; the recorder opens a channel from the first message it sees on a binding id (that host's binding ids are per source, so the binding→channel table is the recorder's, under its ONE mutex `mu_` — there are no atomics), while ONE writer thread drains a byte-budgeted queue into the sink — so plugin push threads never touch the file format and the sink sees a single strictly ordered caller. The default live policy is design decision **D4**: a producer never waits. When a message does not fit `RecorderOptions::queue_budget_bytes`, the largest member of {queued messages, incoming message} is discarded until it does — so the biggest queued message is evicted, or the incoming one is dropped when nothing queued is bigger, and a message larger than the whole budget is never recorded at all. Drops are counted (`RecordingStats`/`RecordingSummary::dropped_messages`) and leave holes, never reorderings: the survivors still drain FIFO. A slow writer therefore costs fidelity, never ingest speed, and never ends a live recording. Downloads may opt into `RecorderOptions::OverflowPolicy::kBlock`: producers wait for budget refunds and admit an oversized message only when no other message is queued or being copied. `requestStop()` ends admission and wakes those producers without waiting for the sink; cancellation must call it before joining producers, then call `stop()` to drain and close. Sink failures also wake waiters. A clean recorder summary is not proof of complete source coverage; the capture owner must gate publication on uncancelled, successful source completion. Truncation is reserved for failures: a sink `write` error truncates with the sink's own message and the rest of the queue is discarded without another sink call (an `addChannel` error truncates but still drains, since the sink itself is healthy); a `close()` that then also fails additionally sets `RecordingSummary::file_incomplete` (the file has no footer and needs `mcap recover`). `stop(terminal_cause)` carries WHY the recording ended into the summary the sink writes, before the close — a truncation overrides whatever was requested, since that is the cause a reader has to believe, and the destructor stops with `shutdown`. Must be owned by a `std::shared_ptr` — `tapFor` hands each tap co-ownership (it calls `shared_from_this()`, so a plain stack instance throws `std::bad_weak_ptr`), which is what keeps a push thread already inside `onMessage` from meeting a destroyed recorder. A truncation does **not** close the sink: the writer thread exits, the file stays open, and no summary exists until the owner — which polls `state()` — calls `stop()` anyway. `stop()` drains, **joins**, then closes, in that order, and is idempotent: later calls — a concurrent one included, which waits for the first to publish — return the same summary without touching the sink again. Failure containment is total: a sink `open()` that throws is a returned error and a `close()` that throws is an `incomplete` summary, a tap call or a sink call that THROWS mid-recording truncates it (the writer thread is `noexcept`; an exception escaping it would otherwise `std::terminate`), the failure transitions themselves allocate nothing before flipping state, and a `start()` that cannot spawn the writer closes the sink into a complete, truncated file rather than abandoning a footer-less one. Format-agnostic (links no mcap) and Qt-free (`recorder_test` compiles `Recorder.cpp` directly against `plotjuggler_sdk::base`, which is what lets it run in the TSan job), so it compiles for wasm too. |
| `RecordingFormat.h` | The on-disk contract of a recorded MCAP file — the `pj.recording` metadata record name, the terminal-cause tokens written into it, and the format version. Channels carry no PJ metadata: a recording holds one source, so its identity is a file-level fact. Shared with the `data_load_mcap` replay path, so changing a name here is a file-format break. |
| `McapRecordingWriter.h` | The `RecordingSink` implementation over `mcap::McapWriter`: one channel per binding (no channel metadata — the source identity lives once in `pj.recording`), schemas deduplicated by signature, 1 MiB zstd chunks — shared by small messages, while a message of 200 KiB or more gets a chunk to itself so a lazy reader never decompresses a video frame to reach a scalar sample — and a checked exclusive-create file sink that surfaces disk failures instead of silently truncating. `close()` fsyncs before it fcloses, so an ok Status means the bytes are on stable storage by the time the user is told the recording ended. `addChannel` refuses past 65535 channels or schemas — MCAP ids are `uint16_t` — so the recording truncates with a reason instead of wrapping ids onto live records. Desktop-only — not compiled for wasm. |
| `RecordingService.h` | GUI-thread owner of at most ONE active capture, and the seam `pj_app`'s Record action drives. One Record press = one batch folder `pj_<UTC yyyyMMdd_HHmmss>/` (created with a bare `mkdir`, so creating it IS claiming it) holding ONE file per recorded source, named `<sanitized display name>.mcap` (NFC-normalised, reserved characters and separator runs folded to `_`, cut to 80 characters, `_2`/`_3` ordinals on a case-folded collision, the writer's exclusive create as the last guard). Each source gets its own `Recorder`, writer thread and queue budget, and every file of the press carries the same `capture_id`. Resolves the recordings folder and the queue budget (`QSettings` keys `Preferences::recording_directory` / `Preferences::recording_queue_budget_mib`; empty directory = `<AppLocalDataLocation>/recordings`; the budget is clamped on load to the Preferences range 8..4096 MiB, and is PER SOURCE, so N sources may hold N times it). `start()` is transactional: it opens every file before attaching any tap, and any failure detaches every target it touched, closes and deletes every file it created, removes the folder if it empties, and emits no `started`. Each `RecordingTarget` describes one source by an opaque `target_key` (pj_app passes the `DatasetId`) plus callbacks (`attach`, which returns false when the source vanished and which a null tap turns into a detach, and `skipped_lazy`), so the service never learns about `DataSourceRuntimeHost`; eligibility is the caller's call, and `pj_app`'s streaming manager filters on `kCapabilityDelegatedIngest` (D1: a direct writer has no raw bytes at the seam) and names the excluded sources beside the targets. Finalization is SYNCHRONOUS on the GUI thread and happens exactly once per recorder: `stop()`, `onSourceEnded(target_key, reason)` (which finalizes ONE source and leaves the rest recording), a poll-detected truncation and the destructor all detach the tap, freeze the source's pure-lazy delta and close that file. A 500 ms poll publishes `progress()` over the live recorders plus the frozen totals of the finished ones, so the totals never decrease; per-source problems are logged, not signalled. `stopped(CaptureResult)` fires once per press once every source has its result: per source a path, a `terminal_cause` and ONE exclusive outcome bucket — `incomplete` (unfinalized: needs `mcap recover`) beats `truncated` (a failure ended the data) beats `lossy` (holes: drops, pure-lazy skips, or a source that ended with a reason) beats `clean` — plus the capture totals, so callers test `clean_count`, never a boolean. ## Linked dependencies

Public link surface (per `CMakeLists.txt`): `Qt6::Core`, `Qt6::Network`, `Qt6::Xml`, `pj_datastore`, `pj_marketplace`, the SDK discovery primitives (`pj_data_source_host`, `pj_message_parser_host`, `pj_toolbox_host`, `pj_plugin_catalog`, `pj_base`), `nlohmann_json`. Private: `tsl::robin_map`, `pj_internal_fmt`, `pj_scripting` (DataProcessorService routes by-id applyFilter through the Luau FilterCatalogue; MarkerService runs whole-series rules through `runMarkerScript`).

The `pj_marketplace` link is conditional: `$<$<NOT:$<BOOL:${EMSCRIPTEN}>>:pj_marketplace>` in `pj_runtime/CMakeLists.txt` links it only on non-wasm builds. On `EMSCRIPTEN`, `pj_runtime` instead adds `pj_marketplace/include` as a private include directory (so `DiagnosticHistory`'s lightweight `QtDiagnosticBridge` type still compiles) without linking the rest of the marketplace module.

`mcap::mcap` is private and conditional in the same way (`$<$<NOT:$<BOOL:${EMSCRIPTEN}>>:mcap::mcap>`): only the recording **sink** is platform-bound, so `find_package(mcap)`, the `McapRecordingWriter` sources and the tests that read an MCAP back are inside `if(NOT EMSCRIPTEN)`. `RecordingService`, `Recorder` and the recording interface headers are built unconditionally; `RecordingService::isSupported()` reports whether this build got a sink, and `pj_app` gates its Record UI on that alone (no compile definition is exported).

## When porting from PJ3

PJ3 wiring into `PlotDataMapRef` / `TransformsMap` becomes wiring into the services above — primarily `CatalogModel`, `SessionManager`, `PlaybackEngine`, and (future) `TransformRegistry`. This is the **one systematic rewrite** during a PJ3 port; everything else should be lifted close to verbatim.

## Tests

`tests/` — gtest-based, with service suites linked into `pj_runtime_tests` using the shared `QCoreApplication` main. `gtest_discover_tests` registers each case as `pj_runtime_tests.<suite>.<case>` and runs it in its own process. Add test sources to `PJ_RUNTIME_TEST_SOURCES` alongside any new service; mock plugin fixtures remain shared-library targets with their paths supplied to the runner.

`recorder_test` stays a separate, Qt-free executable for the TSan target list, with its existing 60-second timeout. `extension_catalog_service_thread_safety_test` also keeps its dedicated target and CTest name for focused concurrency runs. To select the whole module in a configured test tree, use `ctest -R '^(pj_runtime_tests\.|recorder_test$|extension_catalog_service_thread_safety_test$)'` inside the builder image.

`tests/recording_test_utils.h` (the `pj.recording` metadata lookup + the `IsolatedQtSettings` QSettings/QStandardPaths sandbox) and `tests/runtime_host_test_fixture.h` (a real `DataSourceRuntimeHost` over the hermetic catalog and the mock object parser) are shared by the **recording** tests only. The pre-existing host tests (`data_source_runtime_host_object_ingest_test`, `..._stream_swap_test`) are deliberately left on their own fixtures: folding them in would be a large unrelated diff on tests that are not changing.

`tests/recording_pipeline_test.cpp` joins the runtime runner on desktop builds and assembles the whole recording pipeline — real `DataSourceRuntimeHost`s over a hermetic catalog and a real parser plugin → `RecordTap` → `Recorder` → `McapRecordingWriter`, driven by `RecordingService` — and reads the produced files back with `mcap::McapReader`. It covers what no single seam's unit test can see: that a recording started mid-stream captures topics bound before it, that pre-recording pushes never leak in, that two live sources land in two files of one capture (same `capture_id`, ordinals 1 and 2, each holding only its own topics), that a second recording starts from an empty channel table, and that ingest is unaffected either way.
