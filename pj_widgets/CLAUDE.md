# pj_widgets

## Purpose

Reusable Qt widgets and UI helpers — the kind of controls that could be dropped into another Qt application without dragging PJ4-specific state with them. Static library, `Qt6::Core` / `Gui` / `Network` / `Svg` / `Widgets` only.

## Hard constraints (from root CLAUDE.md)

- Depends only on **Qt and the C++ standard library** (plus the dependency-free, header-only `raster/ipc/` wire-protocol contract, which is not a PJ module).
- **No dependencies on `pj_runtime`, `pj_app`, or any other PJ module.** Anything that needs runtime state belongs upstream of here.
- If a widget is specific to PlotJuggler workflows (e.g. plot-specific dockers), it belongs in the widget-family module instead.

| `CurveTreeView.h` | Tree view tuned for PlotJuggler's curve catalog (no runtime coupling — model is plugged in by the caller). Carries the demand-subscription row states as caller-driven decorations: dimming for placeholders/unsubscribed topics (`CurvePath::is_placeholder`/`is_unsubscribed` + `setUnsubscribedKeys`), accent-blue names for force-streamed topics (`setForcedTopicPaths`, marks retained across rebuilds), a one-shot auto-expand armed for a placeholder that later promotes to fields (`requestExpansionWhenPromoted`), and the `placeholderPeekRequested` double-click signal the host maps to a bounded field-discovery subscription. Rows also honor a caller-driven drag opt-out: `CurvePath::draggable=false` makes a curve leaf or object-topic row drag-inert (never starts a drag, excluded from every drag payload) while staying selectable, with the optional `CurvePath::tooltip` explaining why; the `dragAttemptedOnNotDraggableRow` / `dragPayloadKeysSkipped` signals announce the refused gesture so the host can react (PJ4 shows toasts) — the header doc-comments own the emission timing and the complete-vs-drag-payload collector split. The host resolves rows back to catalog items via `catalogKeyOf`/`catalogKeysUnder` (a promoted scalar topic's group row carries no key — its keys live on the field leaves). Also filters by topic kind (`setVisibleCurveKinds` — a topic's 2D/3D scene marker governs its whole subtree; Plot is the by-exclusion bucket) and, when a dataset's topics are all filtered out, keeps the dataset name and shows a caller-supplied message as a muted child row (`setEmptyFilterMessage`). Desktop drags use Qt's native `QDrag` loop; the Asyncify-free WASM build dispatches the same MIME payload through non-blocking Qt drag events while retaining identical drop-site contracts. Per-dataset load progress decoration is caller-driven: `setDatasetProgress` applies a full-set replacement of active ingests, retained across catalog rebuilds. A decorated row is **exempt from the text/kind filter** for as long as it carries progress — it reports work happening right now and owns the affordances that stop it, so hiding it would take the stop button with it (and a ghost row matches no filter text at all); the exemption is applied and lifted by the same full pass that stamps the decoration. Progress renders as a row overlay via a `drawRow` override rather than a delegate (because `QStyledItemDelegate::paint` receives a per-column cell rect and cannot span the row); the shared `progressGeometry(row_rect)` helper returns the fill/caption/keep/discard rects and is the single source of truth for both painting and hit-testing. The bar spans the FULL row width and the right-edge cluster (percentage caption, then the bin, then the ✕, flush to the row edge and the row's full height) is composited on top of it AFTER the base row paint, so it covers the value column and the column separator instead of letting them show through. A loading row's unfilled track is the Accent family's **nominal** tone and the bar its **checked-pressed** rung — the two ends of one ramp, far enough apart that the boundary reads at any fraction (the lighter checked tone sits one step from the tree's selection colour and vanished against it). A loading row **deselects itself and clears the current index**: `QTreeView::drawRow` recomputes selection from the selection model and repaints the selection fill over any background the override chooses, and that fill's right edge at the name-column boundary reads as a stuck ~70% bar — selection and a progress readout cannot visually coexist. For the same reason, selection state must be read via `selectionModel()->isSelected(index)`, NOT from `option.state`, which never carries `State_Selected` in this override. The item delegate strips `State_HasFocus`, so the per-cell focus pill (drawn for the current item independently of selection) never renders in this tree. The indeterminate marquee is phased from animation start (`marqueeBandRect`, a pure function pinned by test), so the band always enters from the left rather than wherever the wall clock lands. The caption is ONLY ever a percentage, never a word. Ghost rows preserve the animation for datasets whose progress terminal is pending but whose catalog entry has already been removed synchronously (when a load fails or is discarded, the entry vanishes immediately, so a ghost keeps the terminal animation alive) — a ghost renders as a top-level entry with the display name and auto-removes after the animation completes. The animation timer runs only while some row is indeterminate or flashing. A cancellable loading row offers TWO stop affordances and the click chooses between them: the ✕ stops and keeps what arrived, the bin stops and discards it, both reported through `cancelRequested(row_key, keep_partial)` — so the host acts on the choice rather than re-asking. Left-button presses in either rect are consumed before the WASM drag-arm logic fires. Both glyphs are painted, not widgets, so they answer `QEvent::ToolTip` themselves (`viewportEvent`) through `stopButtonAt` — the ONE hit-test hover, click and tooltip all share, so a tooltip can never describe a glyph other than the one a click would reach; a bin greyed because the producer cannot discard explains that rather than going silent, while a row past its terminal offers none. Both stay painted (greyed, inert) through the terminal linger so the cluster does not lose cells as the row retires. Hover is tracked from pointer movement (`refreshStopButtonHover`, viewport mouse tracking + `leaveEvent`), not sampled from the global cursor at paint time, which otherwise made the highlight wait for an unrelated repaint. `setGeometryDebugEnabled` draws the row/cell/decoration rects for pj_app's Ctrl+Shift+D inspector, which cannot see rows because they are model items rather than child widgets. |

| `Scrollbar.h` | Fading "scroll pill" (`PJ::Scrollbar`) for a `QAbstractScrollArea`, one instance per axis, in one of two placements chosen at `attach()`. **Reserved gutter** (the `attachPillScrollbars` default, used app-wide): the native bar keeps its `AsNeeded` policy and layout slot — content never sits under the pill, so it can neither cover nor click-steal a trailing-edge control (the old overlay stole e.g. a row's trash button whenever the handle spanned it) — but is painted blank (Paint eaten + `[pjPillBar]` QSS); the pill covers the bar's gutter and mirrors its style-resolved handle, while the native bar keeps ALL interaction (drag, track paging). Rows are compact (`RowMetrics` ~17/22/6 px name/band/gap) so many series stack in a short dock. Rendering reuses the shared `src/TimelineItems.h` items in bottom-ruler mode plus `TimelineScene`'s viewport math; navigation is wheel zoom (cursor-anchored, zoom-out clamped to the display range — the plots' max-zoom-out limit), Shift+wheel row scroll, background drag pan, and a vertical-only `PJ::Scrollbar` pill (the time axis deliberately has NO horizontal scroller — zoom/pan/linked zoom own it). The `pj_plotting` family binds it to the runtime (`StateTransitionsController`/`StateTransitionsDockWidget`). |
| `Timeline.h` | Reusable multi-track Source Timeline: each loaded source is a draggable bar editing only its own per-source display offset (`display = raw − offset`); an **Align** button snaps all displayed starts to the earliest. Its ruler/needle/background QGraphicsItems live in the internal shared header `src/TimelineItems.h` (bottom-ruler-capable, reused by `StateTransitionsView`). Two classes in one `.h`/`.cpp` pair: `TimelineScene` (a genuinely Qt-free timing/geometry/alignment math class — `displayWindow`/`sceneExtent`/`ns↔px`/`barSpan`/`zoom`/`ruler`/`alignStartsToCommonOrigin`/`alignCentersToCommonOrigin`/`alignEndsToCommonOrigin`/`snapToEdges`, plain `qint64`/`double` types) and `Timeline` (the `QWidget`/`QGraphicsView` view). Runtime-agnostic — plain-typed slots (`setTracks`/`setPlayhead`/`setReferenceLine`/`setDisplayRange`) and intent signals (`offsetChangeRequested`/`alignRequested`/`playheadSeeked`/`referenceLineMoved`); the host (`pj_app`'s `SourceTimelineController` for runtime state, `MainWindow` for the reference toggle) does all conversion. Dark Blender-style strip: compact ruler with frame numbers at the top, faint full-height tick gridlines, a diagonal hatch over the empty (non-data) span, and a light-blue tint over the data (OR) span. Two draggable marker needles (one `TimelineNeedleItem` type): the pink **playhead** and the blue **reference line** (shown when the host toggles it on); each darkens + shows a ruler-aligned timestamp pill while grabbed. Ruler ticks and the grabbed-needle pills relabel between **elapsed time** (relative to the ruler epoch — `0:00`, `0:10`, `1.5s`) and the **absolute Unix timestamp in seconds** via `setAbsoluteTimeLabels` (the host drives it from its "use time offset" toggle); this is pure relabelling — bar/needle positions never move. The playhead/range/reference setters take the host's external (playback) frame; `setTimeFrameOffsetNs` supplies the ns gap to the bars' internal frame, which the setters **add** and the seek signals **subtract** in integer ns — so the needle stays bit-exact with the playback cursor even at epoch scale (adding that offset in `double` seconds would round to ~240 ns and desync the two readouts). Navigation: the wheel zooms horizontally (cursor-anchored — the instant under the pointer stays put), a left-drag on empty background pans (a plain background click deselects); the scene keeps a sticky ±1 min buffer so small edge drags don't resize it. A left **name column** lists each track's dataset name, pinned and row-aligned with its bar so the name stays visible when the bar scrolls off horizontally or squashes thin; its right edge is a draggable splitter that resizes the column, and dragging a name row reorders the tracks (`tracksReordered`). Name rows are **multi-selectable** (plain click selects one, Ctrl/Meta+click toggles, Shift+click extends a range), highlighting both the row and its bar; when **≥2 sources are selected** the header's **merge button** enables and emits `mergeRequested` on click (the host confirms + performs the destructive dataset merge); it counts only filter-visible selected sources. Its top band is a **"Datasets" header** (titlebar tone, 2-px-indent title; `timelineDatasetsHeader`/`timelineDatasetsLabel`) hosting the label-less merge button (`timelineMergeButton`, an `SvgButton` with the merge icon, 24-px, self-retinting) on the right — disabled until ≥2 sources are selected. A programmatic dataset filter remains (`setDatasetFilter`, case-insensitive substring; filtering never resets the view/zoom) but has no built-in header UI. The align/reset actions live solely on the app's align rail — there is no kebab menu on the header. Dragging a bar edge-snaps to a neighbour's start/end (orange guide line; `setSnapEnabled`, toggled by the align rail's "snap to" button; drag past the threshold to release). The app's align rail (RHS, `pj_app`) hosts the align-left/center/right + snap-toggle icons at the top and a "reset all" button at the bottom. Both native scrollbars are replaced by canonical `PJ::Scrollbar` overlay **pills** (theme-aware: info-blue on light, pale-grey on dark) — horizontal on the bottom strip, vertical on the right strip — that mirror their scrollbar handles, reveal on hover or scroll, and scroll the view when their handle is dragged. The ruler number line is **sticky**: vertical scrolling moves the rows underneath it while the ruler (and the needles' time pills) stay pinned to the viewport top (`syncStickyHeader`), so the numbers never scroll away with the rows. View-state accessors let the host save/restore the timeline into a layout: `zoom()`/`setZoom`, `viewportLeftDisplayNs()`/`setViewportLeftDisplayNs` (the scroll position, expressed in data-ns so it survives a zoom change), and `nameColumnWidth()`/`resizeNameColumn` (resize the column without disturbing the host-pinned floor); `nameColumnWidthChanged` reports a user separator drag so the host can keep that width sticky. **Auto-zoom** (`setAutoZoomEnabled`/`isAutoZoomEnabled`, default on): on new data (or `fitToContents()`, which the host calls after an alignment) the view zooms so the largest extent — the union of all bars — fills it; an empty timeline always fits the playback range regardless. The app persists the toggle in QSettings and exposes it in Preferences → Plotting. |

| Header | Role |
|---|---|
| `ChromeMetrics.h` | Shared icon/layout spacing constants for dialog chrome, broadcast from MainWindow. Defaults `{icon_size=24, icon_padding=4, layout_padding=2, layout_spacing=2}` — matching MainWindow's first-launch baseline so a dialog constructed before the live broadcast (or one that never receives it) still shows the canonical `titleBarHeight()`. |
| `Hatch.h` | The single app-wide "no data" diagonal hatch: `kHatchSpacing`, `appHatchColor()` (theme ink from `QGuiApplication::palette()`), and `drawHatch(painter, rect, global_origin, color)`. Phasing every caller to the same global grid (`X+Y ≡ 0 mod spacing`, via `global_origin = widget->mapToGlobal({0,0})`) makes all hatches **continuous** — windows into one shared layer, not just same-spacing. Used by `Timeline` (empty span) and `RangeSlider` (unselected track). |
| `Colormap.h` | Shared scientific colormaps (turbo/viridis/plasma/grayscale): the `Colormap` enum, `colorFor()`, `buildColormapLut()` (a CPU RGBA8 LUT for LUT-sampling GPU backends — the 2D depth shader) and `colormapGlsl()` (the *same* polynomials as GLSL, injected into in-shader backends — the 3D pointcloud pass). One source of truth so a scalar maps to the same colour in the 2D and 3D views. Qt-free / no `pj_base` (returns a plain `ColormapRgb`, not `sdk::ColorRGBA`). |
| `StateColors.h` | Stable categorical coloring for state values: constexpr FNV-1a hash of the UTF-8 string → a hand-picked 10-hue colorblind-aware palette (Okabe-Ito + two extensions), so the same state string renders the same color everywhere with zero configuration. Qt-free core (`StateRgb`/`stateColorIndex`/`stateRgb`) + a thin `QColor stateColor(QString)` rim. Palette order is load-bearing (index = hash % size): append, never shuffle — `state_colors_test` pins concrete assignments so a silent recolor fails loudly. |
| `FrameworkTokens.h` | Typed C++ reader over the semantic UI framework palette (`resources/ui_framework.md`). Covers colors — `Surface`, `Variant`x`State` fills + `special()`, foreground ink (`onSurface`/`onFill`/`onSpecial`/`text`/`iconInk`), `outline()` (stateful stroke incl. focus), `overlay()` (alpha state-layers/scrim/hud), selection (`selectionFill`/`onSelection`), `elevatedSurface()`, `gradient()` — **and non-color axes** `space()`/`metric()`/`radius()`/`stroke()`/`duration()`/`type()`. The 4 interaction variants are accent families named by emphasis: **Neutral** (grey), **Accent** (blue), **Highlight** (magenta), **Emphasis** (yellow). The **QSS palette in `stylesheet_{dark,light}.qss` is the single ground truth**; this header holds no values — each call parses (and caches) the compiled stylesheet resource for the requested theme. Self-painted (QPainter) widgets use it because they can't reach the QSS `${token}` engine. `framework_tokens_test` asserts every role resolves in both themes. Beyond the base grid it also exposes the extended semantic families — `status()`, `destructive()`, `progress()`, `sliderHandle()`/`scrollHandleHovered()`, `syntaxInk()`, `contrastInk()`, `diagnostic()`, `onOverlayHud()`, `onCodeEditor()`, `iconInkMuted()` — so **every** colour in the app resolves from the framework palette (the legacy brand tokens and the old `ThemeColors.h` mirror have been retired). |
| `Style.h` | Common style accessors. |
| `SvgUtil.h` | Helpers to load and recolor SVG resources. |
| `VisualizationKind.h` | Neutral `enum class VisualizationKind { Plot, Scene2D, Scene3D }` — the UI vocabulary `VisualizationPlaceholderWidget` emits; the app shell maps the scene families to concrete `"scene2d"`/`"scene3d"` object-widget kinds. |

## UI convention

## Tests

`tests/` holds a focused gtest source per widget whose behavior is non-trivial (e.g. `curve_tree_view_test.cpp`, `messagebox_test.cpp`, `progress_bar_test.cpp`, `credentials_editor_test.cpp`, `layer_list_view_test.cpp`, `colormap_test.cpp`, `scrubber_base_test.cpp`, `file_dialog_test.cpp`, the raster IPC pair). Add ordinary cases to the `pj_widgets_tests` runner in `tests/CMakeLists.txt`, using the shared `MAIN gui` QApplication setup instead of defining a `main()` or creating another application in a test environment. The runner links `pj_widgets`, `pj_resources`, and `Qt6::Test`; `pj_add_test_runner` discovers each case with the `pj_widgets_tests.` prefix and runs it in its own process with a 120-second timeout.

`raster_stream_view_test` stays a separate executable and ctest entry (`RasterStreamView`) because it checks the external helper process's lifetime and uses its own `PJ_STUB_HELPER_PATH` definition. `raster_stub_helper` remains its protocol peer; the target-file path removes any need for sibling-file lookup or a fixed runtime output directory. No test in this module requires a real GL context (`RasterTextGlTest` belongs to `pj_plotting`).

`pj_widgets` has no `docs/` folder — each widget's intent fits in its header doc-comment.
