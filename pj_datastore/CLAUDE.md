# pj_datastore — columnar time-series storage engine

Level-0 foundation library — a **top-level PJ4 module** (app-internal, not part of the `plotjuggler_sdk` package, because plugins reach it only through the `pj_base` C ABI, never by linking it). Owns the in-memory columnar store that every plugin writes to and every consumer reads from: datasets/topics/chunks/columns, adaptive per-column encoding, schema evolution, derived-series DAG (`DerivedEngine`), the opaque-blob `ObjectStore`, and the host-side C-ABI bridges that translate `pj_plugins` calls into engine operations. It also owns the **data-processor execution substrate** — the `PJ::proc::DataProcessor` base and `ProcessorSisoAdapter` that runs a processor as a `DerivedEngine` node (next to the `ISISOTransform` interface it adapts to). That base is deliberately Qt-free *and* script-engine-free, so `pj_scripting` layers Luau filter classes on top of it without this module ever knowing about Luau. Pure C++20 (fmt, tsl::robin_map, nanoarrow); **no Qt, no `pj_plugins` dependency** — `pj_datastore → pj_base` only (`pj_base` comes from the `plotjuggler_sdk` Conan package). It does NOT decode media, choose renderers, own UI/time-display policy, or know about plugin discovery (that is `pj_plugins`). Timestamps are absolute int64 nanoseconds; do not subtract a display base here. Licensed **MPL-2.0** (see `LICENSE`); each source file carries its SPDX header.

- `tests/` — one GTest binary per layer (see `CMakeLists.txt` for the live set; several v3-ABI tests are commented out pending Phase 1b).

- `examples/` — `parquet_import` (gated by `PJ_BUILD_PARQUET_IMPORT_EXAMPLE`).
- `docs/` — see table below.

## Gotchas
- **`readNumericAsDouble()` does not null-check** — returns 0.0 at nulls. Use `isNull()` first, or batch via `readColumnAsDoubles()` which writes NaN at nulls. See `docs/USER_GUIDE.md §5`.
- **Columns can appear mid-stream**: a new field after rows exist seals the current chunk; earlier chunks have fewer columns. Always bounds-check `col_index < chunk->columns.size()`. See `docs/USER_GUIDE.md §6` / `docs/REQUIREMENTS.md §4.5`.
- **`readString()` returns a `string_view` into chunk dictionary memory** — must not outlive the chunk.
- **Transforms have a strict sequential contract**: `calculate()` is called in ascending timestamp order; state persists across chunks and is cleared only by `reset()` before a batch recompute. A late (out-of-order) input commit therefore resets + fully replays the node. See `include/pj_datastore/derived_engine.hpp`.
- **Out-of-order ingest is lossless**: appends accept timestamp regressions; rows sort per chunk at seal, and sealed chunks of a topic may overlap in time. Row cursors (`forEach`, `SeriesCursor`) merge to global timestamp order; `forEachChunk` bulk runs arrive in commit order and may overlap. See `docs/ARCHITECTURE.md` §5. (`DataEngine::flushTo` / `ObjectStore::flushTo` still enforce monotonicity at the streaming swap boundary — tracked follow-up.)
- **`DataEngine` is mutex-guarded** (one `std::recursive_mutex`): a worker thread ingests while the GUI reads. EVERY engine client holds the lock via `lockEngine()` — `DataReader` cursors adopt it for their whole (lazy) lifetime; the C-ABI write host (`WriteCore`/`DataWriter`) takes it at each write-host call (the worker write path); `DerivedEngine` recompute + `addSisoTransform`/`addMimoTransform` take it across their read-modify-write. The raw `getTopicStorage()` accessor does **NOT** lock; a caller must hold `lockEngine()` for the returned pointer's lifetime. The mutex is **recursive** so the same thread may nest (a held cursor + another read; a compound mutator calling another) without deadlocking. `commitChunks` (append) is safe under the lock; chunk-freeing mutations (`clearDatasetChunks`/`retireTopic`/`flushTo`/`replaceDatasetFrom`/`enforceRetention`) are GUI-thread-only and require dropping cached `TopicChunk*` first. When mirroring to the pause/resume **staging** engine, the write host locks BOTH engines in one `std::lock` (`lockEngineDeferred()` ×2) — never hold one engine's lock while plain-locking the other, or it ABBA-deadlocks against `flushTo` (which also `std::lock`s both). The pause/resume `setTarget`/`WriteCore` swap is **not** covered by the engine lock (both racers touch the `WriteCore` object / `state_->core`, not engine state); it is made safe separately by holding `state_->core` as an atomic shared_ptr (`AtomicSharedPtr<WriteCore>`, a mutex-backed stand-in for `std::atomic<std::shared_ptr<WriteCore>>` since libstdc++ only ships that specialization from GCC 12 and the CI baseline is GCC 11) — each worker callback `load()`s a strong reference that pins the core for the call, so the GUI swap can never free it underneath (TSan-guarded by `engine_thread_safety_test`'s `SetTargetSwapVsWorkerEnsureTopicRace`). See `docs/ARCHITECTURE.md` §6.
- **`ObjectStore` is independent storage** alongside `DataEngine`, with its own mutex-per-series threading and lazy/owned payloads — it is NOT covered by `ARCHITECTURE.md`; read `docs/OBJECT_STORE_DESIGN.md`. The two stores' locks are independent and must never nest.
- **`DataEngine::mergeDatasets` is a destructive dataset union** (OR): folds N source datasets into an anchor, each shifted by a caller-supplied raw timestamp delta, **merge-sorting into time-ordered, non-overlapping chunks**. The sort is mandatory: the random-access `SeriesReader` path (`sampleAt`/`indexAt*`) that plots use assumes ascending non-overlapping chunks (only the heap-merging cursors tolerate overlap). Topics/columns union by name (additive; a shared field with a conflicting type is skipped + reported); the anchor keeps its `TopicId`s **and its advertised column order/indices** (seeded from the anchor topic's `columnDescriptors()` even when that topic is empty) so curve keys — `(topic_id, column_index)` — survive; sources are emptied (not dropped). Inputs are validated up front (unknown/duplicate/self source → `unexpected`, nothing mutated); only that validation is atomic. Offset-agnostic (raw shifts in). `ObjectStore` has its own destructive companion merge (`ObjectStore::mergeDatasets`) that the host calls alongside the scalar merge: shared object topic names fuse by shifted timestamp, and source-only object topics reparent under the anchor. Because the merge shifts each entry's store timestamp but never rewrites payload bytes, every shifted entry also records the delta in `ObjectEntry::payload_stamp_shift` so a consumer keying off payload-embedded stamps (e.g. the 3D TF buffer) can land them on the shifted clock (see `docs/OBJECT_STORE_DESIGN.md` → Dataset Merge). See `merge_result.hpp` / `engine.hpp` / `object_store.hpp`.
